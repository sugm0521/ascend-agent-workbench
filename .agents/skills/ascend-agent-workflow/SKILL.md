# 工程任务主入口

读取[根规则](../../../AGENTS.md)与[分层协作](../../../docs/guides/skill-routing.md)。负责目标、授权、任务恢复、领域选择和跨领域协调；领域负责方法选用，原工具负责执行。

## 明确或恢复目标

先复用已有目标、排除项、授权、验收及任务说明，查代码/日志/配置可取得的事实。仅对会改变目标、方案、授权或验收的未决取舍，按项目融合的grilling方法分轮提问并给推荐；信息充分即继续，已有答复不重问。显式grill-me/grilling也在这里处理。

简单问答直接回答。涉及代码/实验/验证/交接时按[材料规范](../../../docs/guides/task-records.md)建立或恢复同一任务，核对owner、计划版本、实际worktree/SHA/dirty和原执行状态，不重复未知运行。定位/审查不自行扩大为修复。

## 选择领域

从[领域索引](../../../upstream/skill-mapping.md#领域入口)按对象与交付目标选择性能、模型精度、算子、部署、模型分析与适配、通用工程、知识报告或工作台维护。不要按工具名字把性能、模型评分、SWE评分或仿真混为一类。

安排首次知识检索在合适层完成；交接已有有效范围，避免每层重查。用户已点名领域/能力时复用偏好，不要求重发或完整重跑主入口。目标未落入索引或覆盖不足时交相关领域按发现协议查询原仓。

## 推进与总交付

复杂依赖按需用[planning](../ascend-task-planning/SKILL.md)，授权推进用[execution](../ascend-task-execution/SKILL.md)，验收/交接用[review](../ascend-task-review/SKILL.md)；简单任务不强制展开。

跨域交接保留原目标、资源/执行绑定、知识查询、输入和失败。新目标或资源/数值语义/必需标准变化按根规则处理；不让两套流程管理同一运行。关键判断反馈证据、假设、选择理由及下一步，不以旧结果冒充当前验证。

汇总领域结果与必要验证，更新同一任务的完成/阶段状态、未验项及资源。新经验可提收录候选，不自动写库、建skill或发布。来源方法见[消费声明](references/upstream-usage.json)，原方法与项目规则冲突时遵循本项目授权/证据边界。
