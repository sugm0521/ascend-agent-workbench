# 清单字段与证据来源

常规部署前和容器总表只使用[统一规范中的三类最小复现记录](../../../../docs/task-records.md#容器总表与最小环境记录)。本说明补充取值来源和独立诊断需要的字段，不能把下表当作每次启动的必填长清单。只采集会影响当前判断的项；缺失标 unknown，矛盾标 conflicting，历史和模拟不作为当前实测。

## 证据来源与按需诊断字段

| 字段 | 记录内容 | 来源与判断 |
|---|---|---|
| 身份/时间 | task、attempt、阶段、采集/证据时间、节点、容器、执行入口、实际镜像ID/digest | 用户目标、实际绑定、执行方记录；不借用其他会话绑定 |
| CANN/驱动 | 实际Toolkit、启用ops/NNAL等组件版本及构建标识，驱动版本、环境入口、有效目录 | 当前版本文件/组件metadata及环境；下载包、安装目录、进程映射分开记 |
| 代码 | vLLM/vLLM-Ascend等实际Git根、完整SHA、dirty、必要patch/未跟踪运行代码引用 | 只读Git与运行模块来源；分支名/包版本不足以定位源码。无Git时记录可核对的构建/镜像/产物标识，不猜SHA |
| PR | 本次明确采用的仓库/PR号、实际采用head/合入提交、merge/cherry-pick/patch方式及后续改动 | 原始任务/提交或已核实GitHub证据；PR号不证明包含其代码。仅历史提及而无法关联本次环境的PR标unknown或未证明采用，不追溯全仓历史 |
| 依赖 | 实际Python及torch/torch_npu等必需包版本、来源；按使用情况列FLA/Triton/Mooncake/DSpark/custom OPP | 目标解释器metadata、direct_url/安装来源及已有manifest；安装版本、文件hash与live加载是不同证据 |
| 替换项 | 组件、旧→新版本、来源release/commit/包SHA、安装路径、授权修改范围、reload需求和已验证阶段 | 本轮安装/构建记录；原始版本缺失标unknown；同一版本文本不足时补构建/产物标识，不每次重hash全树 |
| 模型 | 来源/版本、路径、索引/manifest、量化/辅助配置、元数据patch | 实际模型记录，区分权重与镜像；修改后的配置应有可恢复patch/备份引用。目录名不代表固定内容 |
| 启动/网络 | 最终argv、环境入口和必要非敏感env、可见卡、并行/role/rank、端点及网络用途 | 该attempt实际命令/有效配置；控制与NPU数据平面分别记录，各角色差异保留 |
| 运行/验收 | 进程身份、日志、实际加载证据、请求及原始输出、当前服务/资源状态 | 记录时间绑定实际观察；HTTP/传输成功不代表正确输出，旧成功不覆盖新版本 |

关键取值附来源与观察时间，复用有效证据时引用原时间。只提取所需非敏感字段，不能整包 dump 环境变量、SSH 配置或容器 inspect；SSH 明文口令仅更新确认的本机容器总表，不进入诊断摘要。模拟值不写入真实总表。

## 采集方法和停止条件

- 启动前：读取本次最终环境和代码/包metadata，记录selected；尚无新进程时live_loaded=not_verified。复用有效manifest需保留时间和适用条件。
- 运行中：经所选原执行入口只读核对PID/starttime/进程组或cgroup、解释器及可取得的进程映射。读取proc不可用或动态加载尚未发生时记限制，不发送请求促使库加载。
- 历史整理：只引用已保存材料，字段按原时间分组；不能将后安装包、旧PR和另一轮请求拼成成功环境。
- 本地模拟：使用本地固定输入及历史材料走查规则和输出格式；不连接目标、不运行模型。合成字段与实测字段分开，规则通过不称运行通过。
- 达到请求所需字段及证据边界后停止采集。单项版本问题直接答，不为它全量采集；快照输出不隐含兼容/NPU/精度/性能验收。

## 输出

常规记录直接更新三类材料及所属容器环境版本，启动材料由部署流程保存。独立诊断在已有任务结果中简记问题、必要取值及其时间、结论和缺口即可。仅当前工具确需结构化输入时保存等价的小型清单，不为每次启动同时生成 Markdown、JSON 和长报告。来源不可访问或关键改动未知时明确缺口，不声称完整复现。
