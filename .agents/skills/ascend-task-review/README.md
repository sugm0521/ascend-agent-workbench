# 工程验收与交接

`ascend-task-review` 的使用说明，面向提出任务的使用者；详细执行规则以 [SKILL.md](SKILL.md) 为准。

## 能做什么

核对目标、当前代码/环境、证据和覆盖，形成通过、失败、阶段结果或未验证结论，整理交付和中断交接。

## 什么时候用

阶段/最终验收、独立复核或交接使用；需要实施修复时交执行入口。

相邻入口：[ascend-task-execution](../ascend-task-execution/README.md)、[ascend-skill-candidate-review](../ascend-skill-candidate-review/README.md)。

## 怎么调用

- 使用 $ascend-task-review，复核已有任务的验收证据，区分静态、CPU和真实运行结果，只审查不修复。
- 使用 $ascend-task-review，检查这次推送前预检的失败及未执行项，说明是否需要对具体问题单独同意。

## 需要提供什么

任务/候选、目标与验收标准、实际结果和希望复核的范围。

agent 会先查：当前SHA/环境、详细用例、日志与CI对应关系；复用证据先核对适用条件。

## 会产出什么

可审核的验收结论、覆盖摘要、失败/缺口、推送例外及交接下一步；必要时更新任务状态。

业务仓预检同时核对PR标题结果是否对应当前标题与目标CI规则；代码SHA不变也不直接沿用旧标题结论。细则见[共用预检说明](../../../docs/guides/business-ci-preflight.md#pr-标题只读检查)。

## 操作边界

审查不自动修复或降低标准。允许带问题推送不等于测试通过；未运行NPU或远端CI不记成功，不自动把任务产物推广成公共工具。
