# 任务验收、交接与回顾

读 [根规则](../../../AGENTS.md)、当前任务说明、最新交接和实际证据索引；只在相关问题上定点读 [框架第 11–13 节](../../../docs/项目框架.md)。本 skill 检查可交付结论，不因进入 review 增加原任务的必需范围。

## 核查结论

核对当前模式、目标/排除项、用户决定与验收条件，以及 owner、plan_revision、实际 repo/worktree、SHA、dirty 内容和环境。确认子结果对应本计划；复用旧证据时查明条件。由主 agent 整合冲突，不能把子 agent 摘要直接当验收。

按风险独立检查关键结论、reference、覆盖与集成；无需无理由重跑所有实验。结果标明通过、失败、无定论或未验证，资料不可访问明确标 unavailable；区分源码事实、推断、静态/编译检查、真实路径运行、端到端验收与性能测量。

按目标核查证据边界：定位应有根因/触发条件与影响证据，不声称已修复；模型性能应有可比端到端指标；精度应有确定 reference/输入/标准；部署应有当前目标服务的真实请求；源码学习/纯规划按其产物验收，不强加运行。性能更好不能抵消精度失败。

环境交接按已有验证分别说明产物一致、指定运行用例正常退出、实际模型请求和任务适用的 PD 请求/状态传输证据，不将前一项推作后一项通过，也不要求所有任务补齐全部层级。核查原生兼容或产物报告时按需参考 [工具范围与退出状态](../../../docs/runtime-tools.md)；`running`、截断、不可读或不完整报告保留对应限制。用户要求保留服务时交接实际运行与归属，不自动停服务或标记资源已释放。

审查发现问题时给出位置、证据、影响与建议；未授权修复不自动改业务代码。若已有修复授权，交回执行处理，再核查受影响项。改变支持范围、语义或必需验收需记录用户决定，不静默接受退化。

## 检查矩阵与 CI

`验证矩阵.md` 首页应包含目标、代码/环境、支持范围、reference/阈值、版本、审阅状态和缺口。覆盖摘要按任务适用的生产场景、分支/边界、集成组织，列代表输入、选择理由、通过标准、状态和详细 case/run 引用。

检查摘要能找到详细用例与证据，裁剪有风险/等价覆盖依据；不凑固定 case 数，不铺笛卡尔积。尽量一页仅是浏览目标，不能删必需项。推导输入不能冒充真实生产输入，失败和未验证须可见。

CI 核查 PR、当前 head SHA、workflow/job、run 和终态是否一致，关注分类依据、修改、本地验证、用户审核与新 SHA 复验。queued/running/skipped 不计 success，旧 SHA 绿灯不证明当前 SHA；合入与远程/NPU 验收分别报告。提交/推送默认审核，具体已有授权继续有效；需要新一轮授权时提供可审核结果。

必需项未跑/失败/无定论时，只能交付阶段结果并保留未完成状态，不自行降为可选。completed 必须满足当前模式全部必需验收，不能用文件齐备或演练通过证明真实工程闭环。

## 交付与恢复

主 agent 更新 `交付与回顾.md` 和任务说明，包含目标/结果、主要变更、关键判断依据、验证摘要、CI/PR 状态、证据入口、限制、未完成项、资源处理和下一步。提交/推送/发布前的审核材料应具体可查；已有授权不重复索取。

中断交接另确保当前 owner、plan_revision、代码/环境、实际底层 task/session/run/execution、资源状态、原失败与就绪下一步齐备。核对实际清理结果，不以 completed 或会话结束证明资源释放。新会话无需全读聊天即可继续；恢复先核实状态再接手唯一 owner。

## 简短回顾与候选

记录有效/无效假设、重复探索或返工、覆盖/CI 追踪问题及值得改善的流程。没有候选也正常。

发现可复用操作时只提出具体候选：来源任务与证据、重复性、稳定输入输出、已有能力覆盖、边界、维护成本和验证方式。有持续跟踪价值时交主 agent 记入 `docs/reviews/`，状态遵循 proposed/approved/deferred/rejected/implemented。

不自动复制任务脚本到公共 scripts/，不创建新 skill、不改外部维护源、不全局安装。候选确认后才用 [skill-development](../ascend-skill-development/SKILL.md) 建设；无新增证据不重复推荐已拒绝候选。
