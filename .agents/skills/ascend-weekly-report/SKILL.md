# 两份工程周报

遵循[根规则](../../../AGENTS.md)。维护报告方法；具体运行时间、项目路径和个人调度配置留本机。先读[报告设计](references/report-design.md)，需要解释方法出处时读[来源与取舍](references/sources.md)。

## 输入与取材

确认实际项目根、报告窗口/时区及本机输出目录；沿用调用方已确认值，不重复询问。独立运行从当前项目文件和本机成功回执恢复，不依赖原聊天。首次缺少基线时明确范围，不能把所有已有内容算成本期新增；补报与本期明细分开。

先读小型任务/交付/验证摘要和已有本机日报，再跟进必要日志或产物。结合相关Git历史、暂存/未暂存差异及新增维护文件，纳入用户手工、其他会话和自动维护的工作。成功回执用于定位增量，不取代当前项目事实。发生时间或操作者不明则标待核实，不把mtime、发现时间或聊天标题当作本周完成证据，也不把手工成果算成自动任务成果。

任务记录不足时才在实际项目范围内检索关联会话；跨周长会话按事件时间筛选，父子agent按产物去重。只读取本期线索与受影响内容，不扫描所有历史/skill或其他项目，不复制原始对话、大日志、凭据和内部连接清单。

知识来源由忽略的本机配置 `paths.knowledge_root` 定位，按[知识入口协议](../../../knowledge/README.md)只读相关增量；不要求特定笔记软件。缺配置或不可读时列明覆盖缺口，继续可独立完成的报告，不回退公开正文或执行初始化。分别核对工作台 Git、私有知识 Git（如有）与本机报告状态，不能把一仓推送推断为另一仓成功。

## 组织与核实

- **个人工作周报**：按日写实际做过的工作和产出，再汇总任务增量、失败/回滚、阻塞和已确定下一步；总进度不能代替具体动作。重复轮询合并，值得保留的失败不能省略。
- **项目与知识库改进周报**：写实际修改前后、原因、证据支持的收益与限制；区分已实施、已写入待验证、仅提案待确认。知识新增/补证/纠错/合并/过期历史分别说明；实际提交、推送与未发布状态分开。两份交叉引用，不全文重复。
- 源码/静态、本地/模拟、真实NPU/端到端证据保持各自层级。保留原证据时间，不能用本次重读刷新实验日期。未核实的收益、负责人和下周承诺不编造。
- 检索知识使用[knowledge-curation](../ascend-knowledge-curation/SKILL.md)及[统一证据流程](../../../knowledge/README.md#统一证据流程)，本skill只读知识。需要skill建议时用[candidate-review](../ascend-skill-candidate-review/SKILL.md)，只读受影响入口与证据；先检查手工修改是否已经覆盖，旧提案失效时说明原因。最小建议diff只写本机报告或候选patch，等待用户确认，不应用修改。

报告所称“已推送”须有对应SHA及远端核对来源；只有本地提交则写已提交。没有新的远端回读时标明历史证据时间。本skill不补做发布、远程实验或业务验收。

## 输出与展示

在已确认的本机忽略目录中，每轮创建独立子目录，保留历史：

- `work-weekly.md`：个人工作周报。
- `project-knowledge-weekly.md`：项目与知识库改进周报。
- `index.html`：由这两份Markdown生成的阅读/打印版，内容不另行手工维护。

首次准备按[仓库验证说明](../../../docs/maintenance/validation.md)安装锁定的项目渲染依赖，再用已有Node.js运行渲染器；不依赖作者客户端的私有模块目录：

```sh
node <本skill>/scripts/render_reports.cjs --work <work-weekly.md> --improvements <project-knowledge-weekly.md> --output <index.html> --period "实际覆盖区间" --label "正式周报或有限试写"
```

若运行时需要指定模块目录，仅为当前进程配置`NODE_PATH`；缺依赖时交付两份Markdown并准确说明HTML缺口，不擅自安装。样式在[report.css](assets/report.css)统一维护；不在定时任务中复制模板，不为美化删掉必要明细或制造统计/图表。

## 验收与边界

检查首屏能看懂本期成果、关键限制和待确认事项，主体能回答做了什么/改善了什么，证据定位可追溯。HTML生成后在可用浏览器检查桌面、窄屏和打印布局；没有渲染检查就明确仅生成未视觉验收。避免空表、宽表、长路径挤占正文及待确认事项混入完成项。

两份报告、HTML、来源索引、候选diff与成功回执均留本机，不进入Git提交；输出前确认目录被忽略。成功回执仅在两份报告落盘且本轮范围完成后原子更新，记录覆盖截止、实际输出、来源定位及必要指纹；HTML失败或来源不全时保留缺口，不把部分成功写成完整交付。只报告实际覆盖，不宣称读完全部日志。

本skill不创建调度、不改任务owner/状态、不修改知识或skill、不提交推送、不写全局记忆。普通业务诊断、单次进度问答、单项知识查询不触发完整周报。
