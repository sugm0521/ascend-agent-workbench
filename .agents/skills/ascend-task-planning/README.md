# 工程任务规划

`ascend-task-planning` 的使用说明，面向提出任务的使用者；详细执行规则以 [SKILL.md](SKILL.md) 为准。

## 能做什么

将已明确的目标拆成可验证子任务，确定依赖、责任、写入与资源边界，并按就绪工作安排推进方式。

## 什么时候用

多路径调查、实现与独立验证、跨人交接需要计划时使用；清楚的小任务无需强制拆分。

相邻入口：[ascend-agent-workflow](../ascend-agent-workflow/README.md)、[ascend-task-execution](../ascend-task-execution/README.md)。

## 怎么调用

- 使用 $ascend-task-planning，为这个已明确目标制定可执行计划，列依赖、验收和资源边界，暂不实施。
- 使用 $ascend-task-planning，调整已有任务计划，保留已完成证据和授权，只重排受影响的工作。

## 需要提供什么

目标、范围、完成标准、已定方案与约束，已有任务则指定任务名。

agent 会先查：代码/环境基线、既有进展、依赖与可用资源；不重复询问已决定事项。

## 会产出什么

任务计划、子任务依赖与完成标准，必要时给出责任和assignment、材料入口及修订原因。

## 操作边界

规划本身不授权改业务代码、启动服务、占用设备或发布。委派服从用户授权及适用规则，不固定团队、不为了形式拆任务。
