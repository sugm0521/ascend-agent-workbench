# 固定依赖核对与升级

## 启动与领域归属

本能力由[工作台维护领域](../ascend-workbench-maintenance/SKILL.md)维护；可直接指定，也可由主/领域调用，按[共用约定](../../../docs/guides/skill-routing.md)复用任务和知识查询。具体输入输出、脚本与原验收边界见[SKILL](SKILL.md)。


`ascend-workbench-dependencies` 的使用说明，面向提出任务的使用者；详细执行规则以 [SKILL.md](SKILL.md) 为准。

## 能做什么

核对领域依赖及相关传递依赖，评估上游新能力、已有能力改进、接口和兼容影响；按授权验证切换，并清理已被上游覆盖的本地适配。

## 什么时候用

固定版本核对、依赖漂移或明确升级请求使用；首次接入用初始化，普通代码同步用更新入口。

相邻入口：[ascend-workbench-init](../ascend-workbench-init/README.md)、[ascend-repository-update](../ascend-repository-update/README.md)。

## 怎么调用

- 使用 $ascend-workbench-dependencies，检查本次任务所用依赖是否偏离固定版本，给出影响，不切换版本。
- 使用 $ascend-workbench-dependencies，为指定依赖评估新版本的能力改进、目标组合和回退方案；验证受影响入口，检查旧patch/例外能否清理，再给我看修改。

## 需要提供什么

要核对或升级的来源、目标版本/问题、本轮用途及允许变更范围。

agent 会先查：当前父/子SHA、声明、接口、dirty状态和正在使用的组合；只查本次相关依赖。

完整图、本机路径与验证原件引用保存在维护任务results，公开开发记录仅保留通用方法、公开来源和采用决定。配置指定的来源锁/报告优先于默认位置；必要接入复用init增量步骤。

## 会产出什么

实际与目标版本、上游改进、受影响消费方、采用/暂缓理由、本地patch/例外保留或清理结果、验证分层与回退信息。

## 操作边界

检查请求不等于升级授权，不默认全生态fetch或拉最新。保护运行实验和业务分支，不改外部维护源，不顺带更新业务子模块；发布按具体授权。
