# 工作台依赖维护

## 领域与直接启动

所属[工作台维护领域](../ascend-workbench-maintenance/SKILL.md)。直接启动时复用当前任务，按[分层协作与知识触发](../../../docs/guides/skill-routing.md)完成或复用定向检索，并核对领域适用/补位规则；已有上下文不完整回跑主入口。覆盖不足交所属领域，原方法和工具的授权/验证范围仍适用。


先读根AGENTS.md、本次能力及存在的config/workbench.local.yaml，按[共享配置约定](../ascend-workbench-init/references/config-schema.md#路径与缺省值)定位实际来源锁和相关报告；显式路径不可用时报告缺口。升级图与核验见[依赖检查约定](references/dependency-check.md)。

本 skill 维护直接依赖的选择与受影响链路。下层原声明是约束权威源，上层只存引用和检查证据，不建设第二套 pin、执行服务、身份或资源状态。

## 选择检查范围

- 日常任务只核对本次能力实际使用的依赖及环境，不默认 fetch 或查最新所有生态仓。
- 版本检查先只读核对 path、真实 Git 根、remote、完整 SHA、dirty、声明和实际接口。目录存在或旧 status 不代表能力可用。
- 明确升级时，先读候选父提交的声明，再给出目标组合与验证方案；本轮已授权升级步骤直接推进，提交/推送遵守根规则。不能把“检查升级”当切版本授权。
- 正在运行的实验、业务分支和共享 provider 状态保持稳定。业务组合可以核对，但工具升级不自动 checkout/reset 业务仓或 `submodule update --remote`。

## 从父版本构造受影响依赖图

对 lock 的 `sources` 中本次启用的来源及相关能力，记录当前与候选父 SHA。读取目标父的 `declared_dependencies` 引用、实际依赖文件、gitlink、脚本/参数/结果协议和环境要求；不能先启动旧父的 bootstrap 再猜目标约束。

每个相关节点记录：父依赖/父 SHA、声明文件、用途和启用条件、期望约束、实际路径/版本、拟用版本、检查结果与验证引用。递归读取可访问声明，按真实来源/环境/路径去重，检查同一节点的冲突与循环；不可访问项明确写出文件/父版本缺口。

- workspace remote-dev/coordinator 用目标 workspace 的原声明与原 status/bootstrap 入口。
- knowledge conformance kit 是可选测试依赖，只在相关测试/CI 启用时准备；缺它不阻塞无关运行。
- vLLM-Ascend/vLLM 的声明配对单独核对完整双 SHA 与实际分支；旧开发分支的偏离记录原因，不随领域 skill 升级自动调整。
- Python/DSL、CANN、torch_npu、镜像与芯片按本次任务兼容条件检查；不因资料升级安装或整体升级环境。

涉及原生依赖安装来源或 ABI/退出兼容问题时，可按需使用 [产物清单与原生探针](../../../docs/tools/runtime-tools.md)，核对实际文件、模块来源、可用的已加载库路径及子进程最终退出状态。字节相同不证明运行兼容，正常导入也不证明模型可用；纯声明/版本检查不自动运行探针。工具不实施动态库替换或预加载修复。

## 升级与验证

1. 对比当前/候选父diff，检查新能力、已有能力增强/修复、接口依赖变化及删改/弃用；列受影响节点、项目消费点、本地patch/旧版例外及验证矩阵。按[能力与适配复核](references/dependency-check.md#能力发现入口维护)比较采用价值，不能仅把同方向归为重复。
2. 准备候选约束要求的下层版本，使用可隔离候选目录或原工具支持的定向入口。旧 bootstrap 按旧 pin 工作时不能用它声称准备了目标 pin；不改下层维护源，也不破坏共享在用 checkout。
3. 验证候选父与下层组合及受影响能力：方法按同一问题/证据检查覆盖与结论，脚本核对代表输入输出和失败路径，协议与必要运行效果按环境实测。给出继续旧版、直接采用或保留适配的理由；接口缺失、冲突、循环或必需验证不可执行时只暂停受影响切换，可选未启用项标not_enabled。
4. 全部受影响必需检查通过后切换已验证组合，核对真实父/子SHA与能力入口；同步gitlink/lock、映射和直接引用，删除或改为引用已被上游覆盖的本地patch/旧版例外/重复方法，保留仍必要的项目差异。保存旧组合与回退依据，运行实验维持原基线；提交/推送沿用具体授权。

满足父约束不等于拉到每个项目最新 main。显式开发偏离可以记录版本、原因与兼容证据，不把参考 pin 自动升级为所有任务的硬门禁。branch=main 不授权业务子模块更新。

## 交付与恢复

输出实际/目标版本、上游改进、受影响消费方、采用/暂缓理由、本地适配保留/清理结果、验证层级与回退信息；更新开发记录及相关映射/引用。具体业务状态仍在任务说明，源码判断、静态检查、模拟与真实环境验收分开报告。

必要准备复用[init增量操作](../ascend-workbench-init/references/operations.md#增量检查与补齐)及[发现接入方法](../ascend-workbench-init/references/operations.md#当前客户端的skill发现与接入)，只补已确认差异，不调用完整初始化；初始化也不运行完整升级。完整图和本机证据留维护任务results，公开记录只保存通用方法与采用决定。失败保留原记录，只恢复受影响步骤。

## 消费与吸收复核

按[消费与升级约定](../../../docs/maintenance/upstream-consumption.md)同时检查采用版本到候选、各自有能力历史依据到当前/候选的差量。覆盖主/领域/具体能力/共用模块的真实消费方，JSON事实与Markdown理由分开；未知依据不补造pin。检查已用资源及相关脚本/声明，候选与检查对象不形成全生态回归。只读helper直接读权威配置，前置/状态见该约定，不自动安装或切换。
