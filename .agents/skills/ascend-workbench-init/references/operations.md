# 初始化操作、下层步骤与验收

适用于首次接入、特定缺失项修复及失败恢复。先读取 [配置约定](config-schema.md)，按当前所选 workspace 提交查验工具，不假设本文列出的入口永远不变。

## 下层初始化清单

首次初始化必须将每个启用下层纳入清单。先查根 AGENTS/README、适用 init skill/helper 和当前父提交的传递声明，再按本轮消费方式确定操作；没有 init skill 时读实际安装/使用入口，不另建下层 skill。清单包含：来源/实际路径与 SHA、消费方式、下层入口、必要状态、已存在配置、传递依赖及平台前提、缺失选择、实施副作用与验收证据。全部适用层汇总完再集中确认，不在上层刚得到路径答复后开始实施。

| 下层与消费方式 | 必需核对/收集 | 条件步骤与边界 |
|---|---|---|
| workspace 工作区工具 | 原持久身份、machine profile、资源用户名、统一 alias；适用 repo-init checkpoint | 缺 profile 按原三选项 Git 用户名/随机/自定义；自定义取得实际字符串才完整。alias 用资源名/自定义/不设置。实际候选随 cwd/认证变化须复核；这些不是 SSH 登录用户 |
| workspace 直接远程工具 | 是否复用已有 provider、所需 CLI/MCP 接口、原依赖 pin、实际 checkout、客户端接入位置、平台兼容 | 按原 launcher/default path 接入，已有身份与配置保留；直接 host/port 与管理 resolver 是不同模式，后者不能冒充前者已验证 |
| workspace 任务协调 | 是否本轮使用任务绑定/池执行、coordinator 接口与原状态目录、客户端 hooks 适用性 | 本机任务与远程池分别验收；池执行才要求现有 manager/显式配置。消费方不自动启动或重配 manager；缺口不自动授权安装另一操作系统或迁移整套协议 |
| cannbot 资料/领域方法，或原生插件 | 固定来源、所需入口与引用可读；选原生插件时补具体插件、客户端、项目/全局位置及安装冲突 | 资料读取无需全量安装器；选中插件才检查原 init/quickstart 与外部依赖，保留维护源和版本，针对性 tests 按需 |
| Matt 方法参考，或原版工程流程 | 方法来源与上层引用；选原版流程时补实际目标仓、tracker/工具、domain 与适用 triage 配置 | 原版 setup 配置写入实际目标仓，不写 deps 维护源；方法提炼不要求插件/npm 发布依赖或 tracker |
| model_analysis 可选分析方法 | 固定来源、原 skill/模板、输入来源、项目侧调用说明及实际声明缺口 | 按[调用说明](../../ascend-agent-workflow/references/model-analysis.md)消费；本机资料引用无需新身份/provider，内部 gitlink 来源不明时保持未初始化，产物写任务目录 |
| 其他传递测试/任务环境 | 启用条件、父声明、所需工具/环境与现有状态 | 未选能力明确不启用，不用全量安装使所有行变绿 |

准备方案前核对本机 OS/Python/SSH、既有客户端 provider 与必要模块/接口；可用的只读 summary/status 优先。`workspace_identity.py summary`、`workspace_profile.py summary` 与完整 init 的 probe/plan 有不同副作用，须按当前实现查证。下层版本不可读取或 URL 重定向时查实际来源、目标 commit 与接口布局；替代方案写清原约束、差异与验证，取得用户选择后才 bootstrap，不修改原 pin 隐藏偏离。

## 实施前确认

先只读探测，再形成可审核的本轮方案，并在任何初始化实施操作前集中收齐必需信息：

| 确认项 | 适用条件与需要确定的内容 |
|---|---|
| 范围与能力 | 明确 standard/lightweight 与每个下层的消费方式、本机身份、直接工具、协调、服务器及测试范围；已有明确范围沿用，未启用能力无需追问，不能凭默认 false 判断用户已选择跳过 |
| 私有知识库 | 首次集中确认是否启用；启用后确认本机目录、远端不使用/复用/新建、是否定时维护及同步策略。只收集已选分支的必需信息；已有目录、远端和维护任务复用，详见下文 |
| 业务位置 | 两仓各自复用/专用 clone/子模块模式及真实路径；冲突路径的处置不能由默认值替代 |
| 来源、拓扑与基线 | 实际 clone URL、community/fork、origin/upstream、vLLM-Ascend 基线与 vLLM 配对策略；必要的 fork 创建、既有分支/remotes 变更纳入方案 |
| 作者与账号 | 缺失或拟调整的 Git name/email、GitHub 账号与认证通道；GitHub 昵称/邮箱只能作为作者候选，不能自动视为已确认作者 |
| 下层身份与工具 | 所选 workspace 的 profile/alias、原工具或已有 provider 的复用、客户端接入位置与版本/平台替代；本机工具接入不强制要求服务器信息 |
| 已启用远程环境 | 真实服务器/容器目标、已有 SSH 接入方式及拟实施变化；按原流程取得选择，已知登录用户沿用，不要求用户在聊天粘贴机密 |

每项必须有明确答复或可核实的既有配置/决定；已定项不重复问。异步多问题可能逐项返回，必须检查整个必需项集合，而不是以任意一条答复触发执行。仅确认仓库路径而作者未答复时，整轮初始化实施保持等待，允许继续只读核对和必要记录；禁止 clone、依赖初始化、版本切换、配置写入以及其他初始化副作用。

用户明确缩小范围可以改变必需项集合，agent 不得自行将未答项视为可选或把标准模式降级。首次实施整轮收齐选择；进入实施后新发现的必要取舍暂停受影响操作，先补充确认，不依赖它的已授权准备/验收可继续。原失败和已完成项保留，不回滚或重复成功步骤；恢复受影响操作前核对所需选择齐备，已有授权仍有效且条件未变时直接执行。

## 一份本机报告

报告由主 agent 维护，默认 `.workbench-local/init-report.md`。已有报告作为线索，完成状态必须由当前现状支持。

报告记录工作台根目录、配置 schema、检查时间、初始化模式、owner、启用能力、用户已定选择与授权来源，然后维护操作表：

| operation_id | 目标环境/实际路径 | 期望状态 | 单一执行方/入口 | 依赖操作 | 授权范围 | 状态 | 证据/恢复条件 |
|---|---|---|---|---|---|---|---|

操作状态用 `ready`、`missing`、`pending_decision`、`in_progress`、`failed`、`unknown`、`deferred`；未启用能力单列 `not_enabled`。状态不是任务服务接口。`unknown` 不能直接重跑，应核对是否已发生变化。未知/未验证的权限、CI 配对与 provider 不写 ready。

必需项存在 `pending_decision` 时，本轮初始化实施未获齐备选择，不得将其他待办提前标为 `in_progress`。确认前整理的报告/任务记录可以保存事实和候选方案；不会成为写入业务、本机或 provider 配置的授权。

去重键包含主机/容器或本机上下文、真实工作目录与期望变化。认证按主机/服务/账号/认证通道合并；作者/remotes 按每个实际仓库分别保留。共享 common Git dir 的不同 worktree 不合并其工作目录快照。

## 操作归属

| 准备项 | 默认组织者 | 下层条件与边界 |
|---|---|---|
| 入口、配置、顶层依赖、总报告、界面接入 | 上层 | 顶层仅按 lock 和指定 submodule 路径准备 |
| GitHub 登录与认证通道 | 上层安排一次 | 可以委托原工具；另一层只验收，仓库权限分别查 |
| 业务 clone/submodule、作者、remotes、CI 配对 | 每项操作指定上层或下层之一 | 唯一业务路径；已定选择传入下层 |
| workspace 持久身份、machine profile、执行依赖 | 原 workspace 工具 | 启用相关能力且确有缺失时；上层记录原位置引用 |
| conformance kit/特定环境 | 原声明入口 | 相关测试或任务启用后才准备 |

下层完整初始化会准备未选业务仓库时，不能直接调用。下层没有范围参数时选定向 helper；没有可用 helper 则只暂停相关步骤，给出具体适配方案，不复制第二套业务仓、不改下层维护源。

## 只读现状查询

对配置中每个候选 path，先解析真实路径，再查询 `git -C <path> rev-parse --show-toplevel`。返回根目录必须与预期实际仓库一致，且不是上层/workspace 父仓；未初始化子模块往往会回落父仓。随后用 `rev-parse HEAD`、`symbolic-ref --short -q HEAD`、`status --porcelain=v1`、tracking 查询及 `config --show-origin --get user.name/user.email` 查验。路径未存在、非 Git 仓、错误父根目录分别报告。

只查相关仓库，不为了展示 branch 默认 fetch。ahead/behind 标明缓存 refs 与时间；需要最新远端时单列联网查询/获取范围。remotes 和 fetch/pushurl 检查保留额外配置，输出前移除 URL 凭据。

`gh` 可用、`gh auth status`、所用账号、Git HTTPS/SSH 通道和目标仓权限分别查。API 返回的仓库权限只证明该检查范围，未实测 push 的通道限制如实记录；公共读取不证明账号或写权限。缺认证走官方交互登录与安全存储，不要求聊天粘贴 token。

## 条件使用 workspace helper

当前选择的 workspace 为工具根；执行前查看其真实文件、参数和副作用，任何相对路径都按该入口要求解析。

- `.agents/skills/repo-init/scripts/resolve_vllm_ci_pin.py --vllm-ascend-dir <实际路径>` 支持外部 vLLM-Ascend。它先读 `.github/vllm-main-verified.commit`，旧版本按 workflow/docs 回退，并报告来源。调用前确认该来源属于计划中的 vLLM-Ascend HEAD。
- `repo_topology.py configure --repo <实际路径>` 是有副作用的定向入口，适用明确的新配置；已用 fetch/pushurl/额外 remotes 迁移先检查适用性，不能为便利强行改写。
- `repo_topology.py ensure-main` 会 fetch/准备 tracking 并可能切 branch；它不能作为普通分支查询或 CI 配对后的无条件步骤。`compare-main` 在当前实现会 `ls-remote`，纯本地快照使用原生只读 Git 查询。
- `repo_init_probe.py` 会确保存储持久身份，也可能查询 GitHub；`repo_init_profile.py plan/apply/apply-alias` 也可能确保身份。仅相关能力需要时纳入已授权操作，不为分支总览触发。
- 远程能力按父仓原声明与 `remote_dev.py` / `vaws.py` 的 status/bootstrap 入口核对；provider 接入先用原预览入口，保留用户维护的同名 provider/env/未知字段。不得因缺一个 provider 跑业务完整 repo-init，也不能把 bootstrap 成功当 NPU 运行完成。

下层 skill 的通用 checkpoint 若包含本次已确认选择，传入这些选择并只补真缺口；其未相关的完整流程不加载、不执行。下层必要规则与上层范围无法协调时报告冲突。

## 保存目标与 NPU 接入

用户要求利用本机已有 SSH 时，先只读检查 SSH config/Include、已保存的应用会话和 known_hosts，按真实 host/port/user 去重。保存会话名只是线索，known_hosts 只证明历史主机密钥记录；不解密/打印密码或读取私钥内容，不扫描未保存的地址。已有登录用户、端口、密钥/跳板配置沿用；只有未能查到的必要接入信息才问用户。

服务器总表同时纳入上述全部已保存具体目标和原管理工具已登记目标，按[快照规范](../../../../docs/guides/task-records.md#服务器可达性总表)保留来源、检查时间及失败/未知状态。workspace 旧登记清单使用其真实来源下 `.agents/skills/machine-management/scripts/inventory.py summary`，单项用 `get`；这是旧 VAWS 范围，不代表新 MindIE 全部目标。优先查实际启用来源的只读 catalog/inventory，不能拿旧入口管理新状态；无可用枚举时记录覆盖缺口，不创建 task/session/run 试探。不得调用 put/upsert/remove 或 attach/部署来生成只读清单。

先做有界连接检查，再用原 remote companion 执行只读硬件查询。采用新鲜 `npu-smi` NPU ID 和两种 board 查询，结合 Chip Type/Chip Name/NPU Name 按原 machine-management 规则判定型号；没有 NPU 0 时用实际查到的 ID，不凭 alias、旧 inventory 或镜像名确认 A2/A3。必要驱动库与命令路径按原规则核对。

连接失败、认证/host-key 未验证、硬件未知与已确认无 NPU 分别记录。不可连接不等于无 NPU；没有正面硬件证据的目标不加入就绪环境，不为凑数量推断型号。工具暂停/连续失败时遵循原恢复入口，不盲目重试或绕过；不影响其他本机准备。

发现合格 NPU 后再只读核对现有容器与接入，汇总需要用户选择的复用/新建、具体镜像、密钥变化和管理服务方案；已有明确授权直接沿用。SSH/NPU 探测不是新建容器、安装软件、上传密钥或部署池服务的授权。登记与 ready 验收沿用原机器工具，不在上层保存另一份服务器/租约状态。

现有容器探测结果只作候选证据，不等于用户使用的容器。写入[服务器总表](../../../../docs/guides/task-records.md#服务器可达性总表)前先读本机表中的已确认筛选条件；后续新增须有用户实际使用过的确认或任务证据，不能将全部探测项、名称匹配项或状态查询自动登记为用户容器。

## 新服务器免密接入

本节仅用于用户明确要求接入的新目标，不因列清单、查看状态或保存地址触发。用户已为后续此类目标确认默认补齐免密时，直接复用该授权，不逐台重问；没有这种授权时，公钥写入仍纳入本轮接入方案。

1. 核对目标账号、端口、访问路径及适用的本机现有身份，使用它的公钥；不读取/回传私钥内容，不自动生成或改换身份。无适用密钥、首次登录凭据或必要的主机身份信息时只补问缺项。
2. 主机身份核验与登录公钥授权分开。沿用可信的 known_hosts 或核对所得指纹；未知/冲突保留缺口，不通过关闭校验、删除冲突条目或盲目接受新指纹绕过。
3. 使用现有受授权登录路径，备份目标账号的授权文件，按密钥类型和公钥内容识别已有条目；仅追加缺失项，不覆盖原文件或其他账号。保留原有 from/command 等限制；同一密钥已有受限条目时核对限制，不追加无限制副本来绕过。只修正必需的属主/权限，不重配整个 sshd 或关闭密码认证。
4. 使用全新、明确走公钥且无密码回退的连接验证；不能用已有复用连接证明新公钥可用。记录目标、所用公钥指纹和实际验证结果，凭据不进入命令参数、日志或公开记录。失败时只检查本轮目标/变更，不循环追加或重建环境。

宿主与容器账号、授权文件相互独立；容器独立SSH入口按 [container-ssh](../../ascend-container-ssh/SKILL.md)处理。托管环境继续由原工具执行其支持的接入步骤，上层不覆盖原密钥/身份状态。

## 业务代码与 CI 配对

复用：保留实际 branch、dirty、remotes 和认证，只修本轮授权缺失项。多候选冲突先确认绑定，不能重置旧仓来“统一”。

专用 clone：先查目标目录归属；登记一致的既有 clone 作为重跑成功项，其他占用不得覆盖/删除。使用普通独立 git clone，从已确认 URL 到已确认目标，不迁移旧 dirty，不默认 `--shared`、`--reference` 或 symlink。fork 模式先核对真实个人仓与社区 upstream；fork 不存在时集中确认创建，不能拼 URL 后假定存在/可写。拓扑设置与 tracking 分开记录，后者不能覆盖版本配对。

workspace-submodule：先核对所选 workspace 的 gitlink、业务目标路径与已定基线，再按它的适用定向流程准备该仓。两个业务仓库采用混合模式时，不能跑会创建未选另一副本的整套递归流程。顶层 `deps/` 初始化默认仅指定选定路径；必要递归须证明范围，不使用整个树来图方便。

新仓库配对的完成证据：

1. vLLM-Ascend 实际完整 SHA 等于已确认目标基线；声明文件从该基线读取，记录路径/父 SHA/解析来源。
2. 将解析出的 ref 验证为 Git commit（例如 `rev-parse --verify '<ref>^{commit}'`）；必要获取只按已确认来源与范围执行。tag/branch 解析后固定实际 SHA，不能只保留可移动文本。
3. 正确的实际 vLLM 仓存在该 commit，已授权的新仓 checkout 后 HEAD 等于解析 commit；再次查验两仓 HEAD、branch/detached、dirty 与 tracking，记录完整双 SHA。
4. 声明解析失败、ref 不可获取或实际 HEAD 不符时保留缺口；不能静默改为最新 main。旧开发分支偏离只报告，不为了使表格 ready 自动 checkout。

CI-pinned 配对证明源码组合，不能证明构建、NPU、精度或性能。后续任务按其验证要求单独验收。

## 最终验收与快照

分别报告资料可读、skill 可发现/读取、脚本或 provider 可调用、目标环境适用；不要把文件存在串成全部就绪。

| 能力 | 最低证据 |
|---|---|
| 资料/skill | 实际来源/完整 SHA、路径、所需入口可读，发现/显式读取方式 |
| 代码 | 两个独立 Git 根目录、绑定模式、实际双 SHA、CI 声明核对与偏离 |
| Git 作者 | 两仓有效 name/email 及配置来源；需要修改时为仓库级已授权配置 |
| GitHub/PR | 实际账号、认证通道、真实拓扑及各仓权限检查范围；缺口明确 |
| 远程能力 | 原身份/profile/provider 引用、所需接口状态、实际目标环境验证范围 |

对每个选中 provider 按本轮用途分开核查 checkout/版本、进程启动、MCP initialize/tools-list、适用的实际工具调用和保存配置启动。选中客户端接入时核查实际发现；选中目标运行时核查真实目标，不把远端运行列为只准备本机入口的门槛。失败响应、缺目标输入校验和真实远端成功是不同证据；只有握手通过而实际调用缺平台模块时保持功能缺口。客户端设置先预览，Windows 等平台须检查命令引用、解释器和 hooks；文件写入不代表本会话已加载。生成的本机 provider/hooks/config 保持忽略提交，不改全局信任/权限或覆盖同名 provider。

如果本轮只是直接 SSH 工作而管理 resolver 不适用，只能采用原工具支持的独立 direct 模式并验证，明确缺少管理 selector/session 能力。其他独立能力可继续完成；完整范围有必需缺口时报告阶段结果，不自行缩小范围或宣布全部就绪。用户明确保留缺口后记录新范围与后续恢复条件。

仓库分支总览列仓库、实际 Git 根目录、Codex 主/附加目录、branch/detached、完整 SHA（展示可用 short）、dirty 概况、tracking、查询时间与 refs 新鲜度；依赖另列期望版本/实际偏离。解析根后去重，不把 uninitialized 当业务仓。

工作台保持主目录；业务路径可由用户或可用原生入口附加到项目，报告界面接入是否实际完成。未有能力自动登记时给出两个已绑定具体目录与添加步骤，不能宣称已附加。后续业务 Git/PR/worktree 明确所选 repo，规则和 skill 按任务显式读取。

失败恢复保留已完成项、原失败与具体恢复条件；不从头再跑、不删多余既有副本、不修改 sources.lock 以掩盖偏离。若用户明确将业务/身份初始化留给另一个窗口，只完成本窗口授权的资料或项目构建，并把标准初始化写为未执行。

## 私有知识目录接入

本 skill 统一组织以下选择，消费者按[知识入口协议](../../../../knowledge/README.md)读取唯一 `paths.knowledge_root`；字段见[配置约定](config-schema.md#私有知识库的远端与维护选择)。本机存储、远端同步与定时维护相互独立：仅本地也可定时整理，有远端也可手动维护和同步。不要求笔记软件、固定目录名或 Git 托管。

### 集中确认的知识选项

| 选择 | 选项与仅在适用时收集的信息 |
|---|---|
| 是否启用 | 不启用 / 启用。已有明确绑定和决定沿用；未启用不要求知识路径、远端账号或调度信息 |
| 本机位置 | 复用已有目录 / 创建新目录；确认外部目录及本项目知识子目录。知识根不等于笔记仓 Git 根，不从示例推断路径 |
| 远端方式 | 不使用远程同步 / 复用已有私有仓库 / 新建私有仓库。复用时确认真实仓库 URL、目标分支、对应本地 checkout 与知识子树；新建时确认托管平台、所属账号/组织、仓库名、私有设置、分支与本地落点 |
| 定时维护 | 不启用 / 启用。启用后每项任务选择复用已有 / 创建新任务，确认目的、频率/时间、时区、取材范围和本机输出；现有日/周任务可分别复用或新增 |
| 同步策略 | 使用远端时选择手动提交推送 / 明确授权范围内自动同步。自动同步须明确目标、允许的知识子树/操作及授权依据；定时整理不自动取得推送或知识候选收录授权 |

先核对已有配置、实际目录/Git 和本客户端相关已保存调度任务，形成包含全部适用选择的操作表，再按本 skill 的实施前确认收齐答复。表中说明将创建/修改什么、复用什么、哪些不启用；部分答复不触发提前建目录、clone、建仓或创建调度。已有明确决定传入，不重复询问；不能以目录存在、可读、仓库私有或定时任务已存在代替其他未定选择。明确不启用已有能力时，列出受影响绑定/维护任务的实际变化，一并确认后实施。

### 按所选分支实施与验收

1. **本机绑定**：解析真实目录（含符号链接），核对不在公开工作台内、目录可读、现有 README/topics/history 与内容 owner。按已确认方案创建缺失目录或复用现有目录；迁移正文另核对具体范围，不默认生成全库模板。仅将绑定保存到忽略的本机 `paths.knowledge_root`，保留未知配置。只读路径 ready 不代表写权限、Git或全部初始化就绪。
2. **不使用远端**：不要求 Git/托管认证，不创建仓库、改 remotes 或推送；仍可启用本地定时整理。已有本地 Git 可保留，该选择不删除历史。配置不完整时也不能自动切到其他同步方式。
3. **复用私有远端**：以真实 checkout 核对 Git 根、remote URL/fetch/push 配置、目标分支、私有可见性、作者/DCO、认证和权限；保留 dirty/staged/outgoing 与其他笔记。外部远端尚无本地副本时，只按已确认方案克隆并绑定实际项目子目录；不能把非空目录直接覆盖或接到不明仓。目标公开时暂停知识上传并说明，不自行改变其可见性或另建仓。复用验证不通过实际 push 试权限。
4. **新建私有远端**：只在完整选择确认后，通过实际可用的托管工具创建指定私有仓库，独立回读实际 URL/可见性，再按已定方案准备本地 Git/remote；同名或路径冲突先核对，不覆盖。建仓/绑定成功不等于首次同步成功；首次提交/推送也须在已明确授权和子树白名单内，回读远端 SHA 后才记同步成功。身份或工具缺失时保留具体缺口，不为建仓启用另一套平台/身份。
5. **定时维护**：按当前客户端实际支持的调度入口，先读取匹配项目、用途和真实 ID 的已有任务；复用时只更新已确认字段，保留模型、启用状态等其他设置，不重复创建。新建时使用已选频率、时间、时区及范围；提示读取当前项目规则和本机知识绑定，不嵌入个人路径、私有 URL 或复制一份知识正文。归档/知识维护与周报按各自 skill 执行；未确认知识候选保持待确认，禁止借定时任务向公开仓发布知识。任务目的、实际状态/时间及 ID 回读后才标为已配置；调度工具不可用则记 deferred，不用另建脚本或系统服务替代，不妨碍已就绪的本地知识能力。
6. **自动同步边界**：仅 `automatic` 且已有对应具体授权时，维护任务才可在私有目标中执行授权同步；默认/缺字段、手动模式或无授权时只产出本机结果与待同步项。依照[每日维护约定](../../../../docs/guides/daily-sync.md#检查遗漏并推送)保留其他 dirty/staged，核查所有 outgoing、白名单、DCO、大小和远端回读；笔记仓项目子树不等于整库授权。不使用远端时不创建推送任务或要求同步策略。

把实际选择、操作状态及非机密证据写忽略的本机配置/初始化报告。目录绑定、远端接入、调度配置和首次同步分别验收；未执行的定时运行不称为已验收运行。成功创建的远端/任务改记为 `reuse` 并保存实际 URL/ID，重复初始化先核对实际状态，只补缺失；结果不明时先查询，不再次创建。实际 Git 配置及原调度系统仍是状态事实源，不新建平行服务或同步状态。缺配置的普通业务任务只报告知识覆盖缺口，不运行完整初始化。
