# 工作台首次接入与补齐

## 启动与领域归属

本能力由[工作台维护领域](../ascend-workbench-maintenance/SKILL.md)维护；可直接指定，也可由主/领域调用，按[共用约定](../../../docs/guides/skill-routing.md)复用任务和知识查询。具体输入输出、脚本与原验收边界见[SKILL](SKILL.md)。


`ascend-workbench-init` 的使用说明，面向提出任务的使用者；详细执行规则以 [SKILL.md](SKILL.md) 为准。

## 能做什么

作为初始化总入口，核对并准备所选业务仓、身份、工具、可选知识目录及其维护规范和执行环境，集中确认必要选择并分别验收。

## 什么时候用

首次使用、更新工作台后检查已启用能力的新接入要求，或补齐明确缺项时使用；日常代码同步、固定依赖升级及普通任务不重跑完整初始化。

相邻入口：[ascend-repository-update](../ascend-repository-update/README.md)、[ascend-workbench-dependencies](../ascend-workbench-dependencies/README.md)。

## 怎么调用

- 使用 $ascend-workbench-init，初始化本工作台，先检查已有配置和仓库，集中列出需要我确认的选择，再实施。
- 使用 $ascend-workbench-init，检查当前已启用能力是否缺少新版接入要求，先给差异和补齐建议，不修改。
- 使用 $ascend-workbench-init，按已确认的差异补齐私有知识库接入，保留已有规范，其他仓库和远程环境保持现状。

## 需要提供什么

本轮范围和接入偏好；仓库/身份/知识/执行环境等必要未定项集中确认，已有决定沿用。

agent 会先查：本机配置与初始化报告、现有代码/认证/SSH和所选下层要求；先只读探测再实施。

## 会产出什么

增量检查产出已有覆盖、必要缺项与相关可选项；获授权补齐后更新本机配置与初始化报告，分别列出代码、身份、工具、检查环境及远程能力的就绪状态、缺口和证据。新知识库按确认布局提供操作规范和最小首页；已有库复用原规范，仅补齐已授权缺项，目录可读与维护规范就绪分别报告。

结束时先展示当前可用能力、目标阻塞项和一条可复制的下一步请求，再链接完整报告；没有业务材料时可从[无服务器入门案例](../../../docs/guides/first-task/README.md)体验，推荐入口不会自动开始任务。

## 操作边界

必要选择齐备后才执行clone、配置或安装等已授权步骤；首次明确询问Git上传不限还是字节上限，不把示例当选择。初始化不自动跑业务测试、推送或重启服务；发现旧容器不等于已验证可用。
