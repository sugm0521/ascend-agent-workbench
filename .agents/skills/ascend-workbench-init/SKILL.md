# 工作台初始化

## 领域与直接启动

所属[工作台维护领域](../ascend-workbench-maintenance/SKILL.md)。直接启动时复用当前任务，按[分层协作与知识触发](../../../docs/guides/skill-routing.md)完成或复用定向检索，并核对领域适用/补位规则；已有上下文不完整回跑主入口。覆盖不足交所属领域，原方法和工具的授权/验证范围仍适用。


作为初始化的统一入口，采用“首次完整接入，后续增量补齐”的同一流程。由agent读取现状、汇总必要选择、调用原工具并分项验收，不增加初始化服务或第二套执行状态。

## 先确定范围

先读工作台根AGENTS.md、README.md和存在的config/workbench.local.yaml，按[路径约定](references/config-schema.md#路径与缺省值)定位实际来源锁与初始化报告；操作及验收见[实施约定](references/operations.md)。从已有配置、报告、实际产物和本轮请求判断首次或增量，不因报告缺失或较旧就重新初始化。

- 首次完整核对本项目各领域的实际采用关系、skill发现、业务代码、Git作者、GitHub认证/拓扑/PR条件和必要原工具。双vLLM仓按CI声明配对；按每个来源真实消费方式准备，不全装上游生态所有插件。可选知识库、反馈参与、远程执行/目标和测试分支集中选择，未选项单列；缺真实环境保留缺口，不把源码可读写成运行全部就绪。
- 已接入后的项目更新，只检查受影响的已启用能力及新增要求，先给差异；已有补齐授权才实施。用户要求开启新功能时，将它及必要前提加入本轮增量范围，复用已完成项，不重跑首次问卷。见[增量检查与补齐](references/operations.md#增量检查与补齐)。
- 用户只要求调整知识库、项目改进参与、服务器清单或某项缺失时，定向处理该项；不把明确的小范围维护变成重新完整接入。普通业务不主动运行init。
- 首次仍按[Git推送策略](references/config-schema.md#git-推送策略)集中确认上传大小选择，已有可核实决定直接沿用；未答必需项保持pending_decision。可选[反馈参与](references/operations.md#项目改进参与选择)未答保留未选择，不阻塞其他必需选择齐备的初始化。
- 账号、分支、remotes、fork、SSH key及新增范围的变化沿用具体授权；新服务器按[免密接入约定](references/operations.md#新服务器免密接入)，清单刷新按[保存目标发现](references/operations.md#保存目标与-npu-接入)。查询不扩大为接入或部署。

首次完整范围已明确时，由agent根据本仓实际采用关系查清每项准备要求；不把上游目录当成使用者选单，也不让使用者逐仓决定已采用能力是否准备。仅询问无法查明的身份/路径、真实平台取舍和可选功能；已采用工具不能只因尚无业务任务而直接延期，环境不足列出具体缺口与恢复条件。

## 先汇总下层初始化要求

首次覆盖全部本项目实际采用来源，逐个读取根规则、README、适用初始化入口及父提交的相关声明，形成[下层清单](references/operations.md#下层初始化清单)，再集中确认。增量只读本轮变化或新功能所需范围。配置中的示例默认不代表用户已选启用或跳过。

clone不等于接入完成。区分资料/方法引用、本机身份/profile、直接工具、协调、服务器/容器和测试的真实前提：workspace工具需要时收齐资源用户名/alias；cannbot、Matt等方法引用不要求安装全部原生插件。核对平台、原工具接口、绑定和固定版本，名称相同不代表provider相同。版本不可获取或平台不适用时给出缺口与替代依据，不静默改最新版本或底层状态。

## 核对现状与唯一目标

1. 用只读 Git 查询核对实际 Git 根目录、branch/detached、完整 SHA、dirty、tracking、作者及其来源、remotes 和 fetch/push 配置。未初始化子模块回落到父 Git 根目录时，标记缺失，不能作为独立仓库操作。
2. 以环境上下文和真实工作目录去重。路径别名合并，不同 worktree 的工作目录状态分别核对；不同主机或容器的同名路径不合并。
3. 每个业务仓库只绑定一个实际路径：复用、专用 clone、workspace 业务子模块可以混合选择。默认优先复用；已确认专用 clone 后按该选择准备。`repos/` 或外部绑定不再准备 workspace 的另一套业务副本。
4. 分别核对 Git 作者、GitHub 登录、Git 认证和各仓库推送权限。正确已有状态复用，不能用同一登录代替两个仓库的权限检查；不用实际 push 测权限，不输出凭据。
5. 先读下层脚本的入口和副作用。workspace 的 `repo_init_probe.py` 和 `repo_init_profile.py plan` 会确保持久身份，不能当纯只读探测。分支总览用 Git 查询；provider/profile 只在启用相关能力时准备。

## 一份操作表推进缺失步骤

在本机报告中列每项操作的目标、期望状态、单一执行方、依赖、授权、状态和证据。上下层需要同一变化时合并；委托下层后上层只验收，不并行再做一次。

### 实施前确认

只读探测和上下层清单完成后、首次实施有副作用的初始化操作前，必须完成一次集中确认。首次初始化必须询问Git上传大小策略（不限或指定正整数字节上限），已有明确用户决定可直接沿用。汇总可选知识库的本机目录、远端模式、定时维护及同步策略的全部适用未定项，以及本轮业务仓的路径、来源/拓扑、基线/必要配对、作者/账号，及适用下层的资源用户名/alias、工具/provider 消费方式、版本替代、客户端接入位置和已选服务器/容器方案。先说明哪些能力本轮准备、哪些不启用，再收齐所有必需未定项；配置默认 false 不代表用户已选择跳过下层。已确认或已有可用配置直接沿用，明确未启用的能力不要求无关信息。

**全部必需项得到明确答复或可核实的既有决定后，才能开始本轮初始化实施。** 异步或分组问题只收到部分答复时，保留已回答选项，将未回答项标为 `pending_decision`，等待剩余答复；不能因为代码路径已确认就先 clone、切分支或初始化依赖，把作者等其他必需项留到最后。未提交的预选项、默认值、沉默和等待时长都不代表答复。

等待期间只做资料读取、只读 Git/API 查询、方案整理和必要任务记录；不运行 clone/submodule update、作者/remotes/本机配置写入、登录/安装/profile/provider bootstrap 等初始化实施操作。检查脚本若会创建持久身份，也须经过确认。用户明确缩小本轮范围后，只对新范围重新判断必需项；不能自行缩小已确认范围以绕过等待。详细确认项与验收见 [实施前确认约定](references/operations.md#实施前确认)。

### 按已确认方案执行

1. 首次实施保持全部必需选择齐备的门槛，把已定选择、授权和范围传给下层，避免重新确认。重复初始化/恢复只补新增未定项；实施中出现新必需选择时暂停依赖该选择的操作，先补充确认，保留已完成结果，独立准备与验收可继续。
2. 按 lock 初始化选定顶层 `deps/` 路径，默认非递归。不能无差别运行整个 `deps/` 的递归初始化；限定递归前查明其会创建哪些业务或可选仓库。
3. 只执行待办：复用已有 checkout，或从已确认远端正常克隆到专用路径；不覆盖冲突目录，不把软链接/worktree/shared objects 冒充独立 clone。配置缺失作者时只写已确认仓库级设置，认证共用状态只准备一次。
4. 新业务组合先确定 vLLM-Ascend 基线，解析该提交的 CI-pinned vLLM，再获取并核对真实提交。`status: ok`、目录存在或解析出 ref 不代表完成。报告完整双 SHA 与声明来源，拓扑步骤不得再把配对切回 main。既有开发分支只核对偏离，不自动切换。
5. 下层仅接受已分配步骤。它不支持范围/外部路径时用适用定向 helper；无入口则说明缺口与适配方案，不自动全量 init、改下层维护源或新建下层 skill。
6. 已选择知识库接入时，按[私有知识目录接入](references/operations.md#私有知识目录接入)只补齐已确认的目录、私有远端与维护任务；读取已有库的操作规范；新库按接入协议提供已确认布局的初始 AGENTS.md，已有库不自动覆盖规范。本机绑定仍用唯一 `paths.knowledge_root`，远端与调度选择留本机配置。未选择的分支不实施。
7. 执行后重新核对实际路径、配置与版本。失败保留原结果；重试仅补缺失/失败项，未知中断先查证。成功项不重复 clone/login，缺失只阻塞依赖它的能力。

准备 NPU 运行环境时按 [保存目标与 NPU 接入](references/operations.md#保存目标与-npu-接入) 探测。仅加入连接、硬件与目标环境验收通过的 NPU 目标；无 NPU、不确定和不可连接分别记录。探测授权不自动授权新建容器、安装环境或启动任务池。

初始化不自动升级已用依赖；版本变化交给 `$ascend-workbench-dependencies`，两者共用现状与 lock，不能互相调用完整流程。底层身份、provider、pin、task/session/run/execution 与设备/端口状态仍由原工具管理，上层只记录引用。

## 完成与接入

面向使用者的结束反馈先简短展示“现在能做什么”：依据本轮实际证据列出可立即使用的能力、仍阻塞的目标及具体缺项，再给一条适合用户目标与现有材料的可复制下一步请求，附本机初始化报告入口。未选择的可选能力单独说明，不混作必须修复的阻塞；目录存在、源码可读、工具可调用与运行验收分别表述。不从成功项推断未测能力。增量检查只展示当前可用情况和待确认差异，不执行补齐或开启后续任务。

用户没有业务材料或远程环境时，可推荐[无服务器入门案例](../../../docs/guides/first-task/README.md)；已有真实任务则优先给对应请求。示例只提供可选入口，不自动运行或冒充业务验收；完整路径、版本与接入细节仍在报告，不重复堆进结束摘要。


为业务仓准备开发/PR条件时，按[预检环境发现约定](../../../docs/guides/business-ci-preflight.md#环境发现与隔离)只读识别本机或已登记Linux检查环境，在现有初始化报告记录平台、工具版本、认证/provider引用、用途和查询时间，分别标明静态检查与CPU用例的可用性及缺口。CPU/Linux环境不要求NPU就绪；SSH配置或密钥存在只说明有候选，不证明连接与环境可用。不在初始化运行业务测试、上传业务快照或擅自安装系统依赖，逐轮预检重新核验即可，不重跑完整init。

将实际接入范围、路径（包括可选 `paths.knowledge_root`）和已定选择保存到忽略提交的本机配置；报告分别验收资料/skill、代码、作者/GitHub、下层本机身份、直接工具、协调能力与远程目标。provider 的源码、启动、接口枚举、实际调用、客户端加载分别验收；不能以 tools/list 成功冒充功能可用。平台缺口不能自行转成安装 WSL、迁移协议或部署服务，新增选择先确认，已就绪的独立能力继续交付。

报告包含带查询时间的仓库分支总览与依赖声明偏离。默认不为总览 fetch，ahead/behind 写明引用新鲜度。保留工作台为 Codex 主目录；按需附加两个实际业务目录，分别记录“agent 可访问”与“界面已附加/待操作”。clone 不等于界面登记。原生主仓 PR/worktree 操作不能误用到业务代码，业务 Git 操作始终指定实际 repo/worktree。
