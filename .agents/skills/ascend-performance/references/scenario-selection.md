# 域内场景与来源选择

从本域SKILL按目标进入，只读取相关行及原资源。表中候选未承诺工具就绪；与当前后端/输入不适用时只保留方法范围，不另建运行状态。实际采用记录在upstream-usage.json，原资源路径按lock/本机配置解析。

| 场景与输入 | 本域方法/原资源定位 | 条件与边界 |
|---|---|---|
| C01 服务吞吐、TTFT、TPOT、prefix压测 | 项目performance-benchmark → aisbench_auto_tools_prefix原工具；定位：[ascend-performance-benchmark](../../ascend-performance-benchmark/SKILL.md)（主入口）、[workspace/vllm-ascend-benchmark](../../../../deps/vllm-ascend-workspace/.agents/skills/vllm-ascend-benchmark/SKILL.md)（条件替代） | workspace benchmark仅在负载不适用AISBench时评估；msagent run-aisbench-evaluation主讲数据集精度，不能替换性能压测 |
| C02 端到端推理调优 | 项目inference-optimization；定位：[ascend-inference-optimization](../../ascend-inference-optimization/SKILL.md)（主入口）、[workspace/vllm-ascend-performance-regression](../../../../deps/vllm-ascend-workspace/.agents/skills/vllm-ascend-performance-regression/SKILL.md)（条件方法） | 基线用C01；证据按profiling/显存/算子场景选；regression消费可比结果；不默认执行上游完整调优循环；不以仿真或单算子收益替代模型实测 |
| C05 已有AISBench结果整理 | 现有AISBench证据报告工具与原生评测器 | 异常输出转模型精度场景；不发新请求，不修改官方评分；不是另一套评测runner |
| E01 数据采集/框架插桩 | 已有服务按workspace collection方法和当前工具；代码插桩参考msagent采集适配；定位：[workspace/ascend-profiling-collection](../../../../deps/vllm-ascend-workspace/.agents/skills/ascend-profiling-collection/SKILL.md)（现有方法）、[msagent/ascend-profiler-collect-adaption](../../../../deps/msagent/skills/profiler/ascend-profiler-collect-adaption/SKILL.md)（插桩补充候选）、[cannbot/model-infer-profiling](../../../../deps/cannbot-skills/model/model-infer-profiling/SKILL.md)（参数补充候选） | cannbot model-infer-profiling只补目标框架/版本采集参数；先查框架内建开关；已有数据不重采；工具版本参数另核 |
| E02 已有数据完整性/可分析性 | msagent profiler-data-validation作为方法候选；定位：[msagent/ascend-profiler-data-validation](../../../../deps/msagent/skills/profiler/ascend-profiler-data-validation/SKILL.md)（方法候选） | 只检查影响当前分析的产物；不因缺可选文件全量重采 |
| E03 整体报告、step/layer与跨rank对齐 | workspace profiling-analysis方法/适用解析入口；定位：[workspace/ascend-profiling-analysis](../../../../deps/vllm-ascend-workspace/.agents/skills/ascend-profiling-analysis/SKILL.md)（现有主方法）、[ascend_agent_skills/ascend-profiling-anomaly](../../../../deps/ascend-agent-skills/skills/ascend-profiling-anomaly/SKILL.md)（专题补充候选）、[msagent/msagent-profiler-breakdown](../../../../deps/msagent/skills/profiler/msagent-profiler-breakdown/SKILL.md)（DB拆解候选） | ascend-profiling-anomaly补空泡、等待锚点或trace结构；msagent breakdown补DB场景拆解；仅补原报告缺口，不同时产出多套互不一致完整报告 |
| E04 DB schema/SQL精确查询 | msagent DB explorer已采用的方法引用；定位：[msagent/ascend-profiler-db-explorer](../../../../deps/msagent/skills/profiler/ascend-profiler-db-explorer/SKILL.md)（已采用方法；工具待验） | 须确认schema与安全只读查询通道；其“唯一首先触发”不扩大到所有性能任务；MCP未验不声称可执行 |
| E05 DB集合通信等待/带宽/快慢rank归因 | msagent communication-analysis已采用的方法引用；定位：[msagent/ascend-communication-analysis](../../../../deps/msagent/skills/profiler/ascend-communication-analysis/SKILL.md)（已采用方法；工具待验） | 缺少DB时仍可按workspace现有产物方法分析；当前该方法P2P覆盖不完整；仅高耗时不能证明链路瓶颈 |
| E06 计算热点、Host调度与CPU绑核 | 按证据分别选msagent computation、schedule、cpu-binding专题；定位：[msagent/ascend-computation-analysis](../../../../deps/msagent/skills/profiler/ascend-computation-analysis/SKILL.md)（已采用方法；工具待验）、[msagent/ascend-schedule-analysis](../../../../deps/msagent/skills/profiler/ascend-schedule-analysis/SKILL.md)（已采用方法；工具待验）、[msagent/mindstudio-cpu-binding](../../../../deps/msagent/skills/profiler/mindstudio-cpu-binding/SKILL.md)（绑核专题候选） | 只加载与瓶颈判断有关的专题；不能三个全部跑一遍；优化须回归目标负载 |
| E07 vLLM服务HBM权重/KV/HCCL拆分 | workspace memory-profiling方法；定位：[workspace/ascend-memory-profiling](../../../../deps/vllm-ascend-workspace/.agents/skills/ascend-memory-profiling/SKILL.md)（现有方法） | 按实际服务和当前工具取证；不以训练/GE内存数据替代vLLM组件证据 |
| E08 msMemScope dump、泄漏/OOM | msagent memory-analysis已采用的方法引用；定位：[msagent/memory-analysis](../../../../deps/msagent/skills/profiler/memory-analysis/SKILL.md)（已采用方法；工具待验） | 已有dump先解读；无数据时才评估采集；与E07数据契约不同；OOM不是必然使用msMemScope |
| E09 两个集群/Prof数据集对比 | msagent cluster-compare/prof-compare方法候选；定位：[msagent/ascend-cluster-compare](../../../../deps/msagent/skills/profiler/ascend-cluster-compare/SKILL.md)（集群对比候选）、[msagent/ascend-prof-compare](../../../../deps/msagent/skills/profiler/ascend-prof-compare/SKILL.md)（Prof对比候选） | 先对齐工作负载、采样窗口和schema；GPU/NPU或跨版本不等价的窗口不能强行作因果比较 |
| H01 HCCL打流与环境 | 项目alltoallvc打流入口；其他集合操作查ascend hccl-test；定位：[ascend-hccl-traffic-test](../../ascend-hccl-traffic-test/SKILL.md)（主入口）、[ascend_agent_skills/hccl-test](../../../../deps/ascend-agent-skills/skills/hccl-test/SKILL.md)（其他集合操作候选）、[cannbot/hccl-env-check](../../../../deps/cannbot-skills/communication/hccl-env-check/SKILL.md)（环境补充候选） | cannbot hccl-env用于环境专题；alltoallvc与AllReduce/AllGather不是相同测试覆盖，msagent通信trace不是打流验收 |

方法不足时按[依赖能力发现](../../../../upstream/skill-mapping.md#依赖能力发现入口)查询已登记来源，足够即停。候选选择或上游更新影响本域时核对新增/增强/修复及旧适配，采用后同步消费声明与受影响引用。
