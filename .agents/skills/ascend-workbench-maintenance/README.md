# 工作台维护

项目自有领域入口，统筹细分目标、自有/上游选用、证据与交接。完整流程见[SKILL](SKILL.md)，来源与输入细节按需读取，不预加载全部依赖。

- 可以从主workflow进入，或直接指定本skill；具体能力也可直接开始，均复用同一任务上下文。
- 接入示例：首次用init完整准备项目；后续更新或开启新功能只补新增要求，复用已有配置，不重新跑完整接入。
- 示例：检查相关上游变化与自有能力待吸收项，先不切版本。
- 使用反馈示例：使用 $ascend-workbench-maintenance，整理本次skill问题的本仓Issue草稿，先给我看完整资料，不对外提交。
- 输入：当前目标、已有材料、实际版本/环境与授权；输出：选用方法、结果/证据、验证范围、缺口及下一步。
- 首次目标/新错/条件变化按[共用约定](../../../docs/guides/skill-routing.md)定向查知识，已覆盖结果复用；不自动写库、升级来源或扩大运行授权。

反馈流程见[使用反馈与投稿](references/skill-feedback.md)。初始化可选择是否参加项目改进；未选择/不参加时不主动邀请，手动要求反馈仍可处理。参加只控制邀请，每次公开发布都须审核当次收集材料与最终内容；历史批准不能代替。
