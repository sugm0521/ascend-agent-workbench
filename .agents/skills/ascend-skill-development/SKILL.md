# 自有 skill 评估与开发

## 领域与直接启动

所属[工作台维护领域](../ascend-workbench-maintenance/SKILL.md)。直接启动时复用当前任务，按[分层协作与知识触发](../../../docs/guides/skill-routing.md)完成或复用定向检索，并核对领域适用/补位规则；已有上下文不完整回跑主入口。覆盖不足交所属领域，原方法和工具的授权/验证范围仍适用。


遵循 [根规则](../../../AGENTS.md) 与 [框架第 6、13 节](../../../docs/maintenance/项目框架.md)。读取当前环境可用的 `skill-creator` 规范；先查 skill 目录/能力目录的实际入口，不把某台主机的绝对路径当作必需依赖。规范不可访问时说明缺口，不声称按该规范完成验证。

## 先判断是否值得建设

候选价值、去重与最小改动范围统一使用[skill-candidate-review](../ascend-skill-candidate-review/SKILL.md)评估；已评估且范围未变时直接复用结论，不重复全量评估。实施中发现需要增加规则或检查时也按该入口收敛，不把候选清单全部变成默认流程。

未经用户针对具体新候选确认，交付 proposed 候选，不能创建其 skill 目录。批准维护计划不代表批准全部候选；已明确批准的初期建设或具体修改范围按授权直接推进，不重复批准常规编写/验证。删除或合并整个 skill、改变功能范围或必需验收标准、增加未授权依赖另提交具体建议；已授权优化中清理被替代的重复文字、改为引用和更新调用方属于常规实施，不逐段重新询问。

公共脚本候选与 skill 候选分清：确定性重复操作可能适合脚本，决策/路由流程可能适合 skill，不为了完整性同时创建两套。上层编排经验归本项目，领域知识遵循原来源机制，不自动发布到多份知识库。

## 开发已确认 skill

维护源为 `.agents/skills/<名称>/SKILL.md`，使用小写字母/数字/连字符与准确 YAML name/description。描述解释实际能力和触发边界，避免把普通业务请求误路由到 skill 开发。先确定输入、输出、流程约束和授权，再写最短可用入口。

新增自有 skill 时，同步提供面向使用者的 `README.md` 并纳入[项目功能索引](../../../README.md)：说明功能、适用场景、调用示例、输入输出和操作边界，详细流程链接 `SKILL.md`，不重复维护。修改现有 skill 时，功能、场景、输入输出、示例或操作边界变化才同步对应 README；名称、路径、分类或用途摘要变化，以及已获授权的删除/合并，同步受影响的总索引和引用。功能、输入输出或操作边界变化时，还须检查受影响的使用指南、模板、配置说明及其他 skill 调用约定，同步失效内容；交付时列明更新项或无需更新的理由，不扩大为无关文档清理。仅内部措辞或步骤整理且用户用法不变时，核对说明仍准确即可，不为同步制造无意义改动。

通用规则引用 [AGENTS.md](../../../AGENTS.md)，不大段复制框架；引用根文件从 skill 目录使用真实可解析相对路径。仅在条件内容或确定性操作确有必要时添加 references/、scripts/ 或 assets/；附属资源有明确调用入口，按需加载。需要 UI 元数据时按当前 skill-creator 的 openai.yaml 规范创建，默认保留自动发现，不因有审核动作推断为 explicit-only。

新增、替换或迁移规则时，明确唯一维护位置，检查本次受影响的旧规则、入口及调用方；被替代的重复正文删除或改为引用，调用方指向当前入口，不只叠加新规则。仍有独立作用的规则保留；迁移时删除旧位置及兼容跳转，当前调用方统一指向正式入口，不扩大为全仓清理。

按 [来源与能力映射](../../../upstream/skill-mapping.md) 核对实际锁定来源。借用实质内容记录来源、版本、修改与许可；Matt 方法按目标提炼，不能大段复制或携带其环境假设。`deps/` 外部维护源只读，不能把消费上游变为改写上游。

按[跨机器复用规则](../../../docs/maintenance/validation.md#开发与发布的跨机器复用规则)检查 SKILL.md 及全部附属资源：必需参考随仓维护或来自可获取的固定来源；本机报告只用于提炼，不携带原件及其索引，也不把个人全局安装作为必需依赖。运行输入用使用者参数、本机配置或能力发现定位；通用示例不能填入开发者实际机器值。避免硬编码工作目录、主机、阈值或工具命令；使用本任务实际路径与能力发现。其他主机缺个人 source/deploy skill 时报告缺口或使用已查证替代入口，不声称能力已安装。新 skill 不授权全局安装，不覆盖独立同名版本。

## 验证与交付

1. 用可用 `skill-creator` 的 `quick_validate.py` 验证格式，检查本 skill 与引用资源确实可发现、路径存在且描述有区分度。校验器通过仅证明其检查范围。
2. 为代表请求核查目标是否正确、不会多余追问/委派/修复或越权，至少包含适用与容易误触发的不适用请求。复杂关键流程适用时在隔离环境做行为演练；只模拟时明确标记，不伪造远程/NPU/CI 验证。
3. 新/改脚本验证实际输入输出、失败和幂等/重试行为；涉及脚本、必需依赖或执行入口时，使用候选隔离副本按公开说明准备依赖，覆盖实际路径和缺依赖处理。仅改流程/reference 时核查公开引用与代表请求，至少走查“其他机器没有作者本机材料/个人 skill”的分支，不增加仅复述文本的测试；格式校验器的本机位置不成为发布依赖。
4. 交付前对照本轮变化核对 README 与执行规范一致、总索引及受影响导航完整；发生规则替换或迁移时，核对旧规则、入口与调用方已完成替换，说明已移除/改为引用的内容，以及保留项的独立作用。链接检查通过不能代替内容准确性和新增入口覆盖核对。报告实际修改、说明/索引已更新或无需更新及理由、格式/引用检查、行为验证和未执行项，更新已确认建设的工作台开发计划、实际开发记录与当前本机任务中的候选决定；原任务证据保留对应关系，不为工程知识建立建设待办。

授权范围内的验证失败先窄修复再验证，不把每次失败堆成新规则。无真实 token 用量时只报告结构/字符数变化，不声称节省比例。业务交付、静态演练和真实执行成熟度分别说明。
