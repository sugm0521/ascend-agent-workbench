# vLLM-Ascend 推理性能调优

遵循[项目规则](../../../AGENTS.md)。本入口负责选择下一项值得验证的改动，实际服务、资源、负载和分析复用现有能力；授权沿用任务范围。新任务先确认目标，已有任务直接恢复当前证据和下一步。

## 固定目标与可比较基线

从用户输入、已有脚本和运行记录查明以下信息；只追问无法查到且影响验收的缺项：

- 模型/权重/量化与 tokenizer，vLLM 和 vLLM-Ascend 的实际源码、patch 与加载路径，芯片、驱动、CANN、torch-npu、原生扩展和拓扑。
- 输入/输出长度分布、请求数、并发或速率、prefix/缓存状态、流式/采样/停止规则、预热、重复次数和已有精度要求。
- 目标指标的原生来源、单位、阈值和聚合方法；用户只给吞吐目标时，不另设延迟门槛。需要明确而尚缺失的负载或统计口径时，保留待确认，不以任意合成负载宣布达标。

按[运行环境复现入口](../ascend-runtime-snapshot/SKILL.md)记录足以复现本次实验的条件。复用旧容器时先只读核对镜像、挂载、editable 源码、额外安装、替换库和启动环境；镜像标签或包版本相同不证明环境一致。

使用[性能压测入口](../ascend-performance-benchmark/SKILL.md)驱动 AISBench，保留原生结果。检查成功/失败请求、实际输出 token、长度/提前停止、重复测量波动。正式性能轮与 profiling 轮分开。已有有效基线先复用，环境/负载变化会影响结论时再刷新。

按[统一登记边界](../../../docs/guides/task-records.md#三类正式测试总表)，正式基线和最终验收按目标进入性能或精度测试表；内部摸底、候选筛选和排障只保留在本调优任务，包括失败和中断，不因用户要求查看结果或日志就进入正式表。精度诊断按对应 skill 的远端材料规则执行。

PD、每卡归一化指标或跨机环境复刻时，读取[PD 与验收口径](references/pd-and-acceptance.md)。

## 从证据选择候选

根据当前缺口选择轻量检查；已有 profiling 足够时，按[分析输入与方法](references/sources.md#分析输入与方法)先确认产物、窗口和当前判断，再用[能力映射](../../../upstream/skill-mapping.md#按任务选用与重叠处理)定位具体专题。仅当新增采样能区分关键假设时采集。分析方法与[运行后端](../../../upstream/skill-mapping.md#运行体系与执行入口)分别核对：旧脚本的身份、目标解析必须兼容当前工具；缺后端时只复用输入满足的离线方法，不能伪造session、创建第二套资源状态或把换仓当作已适配。

先确认瓶颈位于 prefill、decode、调度/Host、内存还是通信，结合关键路径和源码实际分支解释；按需读取[Ascend 候选选择](references/ascend-candidates.md)。算子耗时之和、占比和理论上界都不能直接作为端到端可获得收益。

每个保留的候选写清：

| 字段 | 内容 |
|---|---|
| 证据与假设 | 同一捕获/负载下的指标、事件或源码位置；什么现象会否定假设 |
| 改动与适用条件 | 唯一主要变量，实际芯片/版本/shape/执行模式；确认参数被支持且路径生效 |
| 预期与成本 | 哪项指标应向何方向变化、显存/启动/通信成本；数字收益仅引用实际测量 |
| 验证与回退 | 对照负载、必要精度/功能检查、停止条件和恢复方法 |

优先验证证据最强且成本合理的少量候选。已有配置可解决的问题先做配置实验；证据指向算子或框架时按任务授权进入对应代码路径。量化、近似计算、接受率语义或支持范围变化沿用原验收与授权，不能为达吞吐目标自行降低输出质量。

## 执行与判断

- **配置调优**：显式声明允许变化的服务参数、拓扑或资源数量，其余负载和条件固定；每个候选重新计算实际资源分母。拓扑变化作为部署方案比较，保留延迟、成功率及资源差异。
- **代码优化**：保持非代码条件一致，使用可用的受控 A/B 方法；确认原有回归工具是否要求相同配置，不能把配置搜索硬套入其代码对照契约。
- 按现有运行工具确认设备占用和本任务所有权，顺序执行竞争同一资源的测量。不能停止他人服务或修改用户要求保留的源容器；源环境取证与任务实验副本分别记录。
- 先做最小真实路径检查，再测正式指标。记录每次运行的原生结果、配置、版本、有效样本、失败及波动；根据预算与观察到的波动安排重复和交替顺序。
- 代码/后端/图模式/量化等变化按实际影响调用[精度入口](../ascend-model-accuracy/SKILL.md)或现有算子/功能验证。确认目标算子、图分支和库实际加载；替换文件存在或 HTTP 成功不代表候选路径正确。
- 候选无收益或退化时恢复已知状态，保留证据并修正假设。连续失败且无新证据时停止该方向；达到任务预算或遇到资源、精度、环境复刻缺口时准确交付阶段状态。

## 交付

交付基线与各候选的指标表、采用/放弃理由、最终可复现配置、性能与精度证据、未完成项及资源状态。目标已达到和相对基线有统计支持的收益分别判定。仅静态/模拟通过时标明该层级；必需真实验收未完成不宣称调优成功。通用 skill 不保存本次机器、凭据、固定业务阈值或私有证据索引。
