# 已授权任务执行

`ascend-task-execution` 的使用说明，面向提出任务的使用者；详细执行规则以 [SKILL.md](SKILL.md) 为准。

## 能做什么

在已确认范围内推进调查、实现、实验和CI修复，记录候选、环境、验证证据及下一步；支持中断恢复。

## 什么时候用

已有明确小任务或计划需要落地时使用；目标尚不清晰先走总入口，独立验收交给review。

相邻入口：[ascend-agent-workflow](../ascend-agent-workflow/README.md)、[ascend-task-review](../ascend-task-review/README.md)。

## 怎么调用

- 使用 $ascend-task-execution，继续已有任务，先核对基线和未提交工作，再执行已经确认的下一步。
- 使用 $ascend-task-execution，对指定业务改动做格式检查和相关CPU预检，不跑NPU，不修改业务代码，不提交推送。

## 需要提供什么

任务/计划或清楚的小目标、修改与运行授权、禁止项和完成标准。

agent 会先查：实际repo/worktree、已有任务记录、代码/环境及原执行工具；恢复前查询未知运行状态。

## 会产出什么

实际改动或调查结论、命令/配置、退出状态、验证结果、限制和交接入口。

业务仓预检包含按目标CI规则进行的PR标题只读核验，区分实际标题、拟标题和不适用；不修改PR标题或描述。细则见[共用预检说明](../../../docs/guides/business-ci-preflight.md#pr-标题只读检查)。

## 操作边界

定位/审查授权不包含业务修复。推送前预检按共用规则选静态/CPU检查，不自动跑NPU；普通业务实验另按明确授权，不能将预检边界泛化为所有任务禁止硬件验证。
