# 授权任务执行

先读 [根规则](../../../AGENTS.md)、当前任务说明或 assignment，再按需加载 [能力映射](../../../upstream/skill-mapping.md) 中适用领域 skill。执行复杂实验/CI 时定点读 [框架第 9–12 节](../../../docs/项目框架.md)，不重新运行上层完整规划流程。

## 核对后开始

核对 task_id、owner、plan_revision、目标、授权、完成标准、输入依赖、实际 repo/worktree、SHA 与影响任务的 dirty 内容。读取目标业务仓库规则。assignment 接收者仅写分配范围；整体状态、计划和最终报告由主 agent 维护。

核对工具前置条件、副作用、实际路径及底层身份映射；复用现有执行/session/资源机制。维护源 `deps/` 默认只读，与授权修改的业务 checkout 区分。缺少远程/NPU/模型仅阻塞对应步骤，本地查证和其他就绪工作继续；未知中断运行先查证，不重复启动或占用。

“定位/分析/审查”只交付证据和建议，可在隔离环境验证假设，不自动改业务代码。“修复/解决/优化/实现”在确定范围内连续改动和验证。必要记录遵守显式完全只读限制。

## 调查、实现与实验

处理新报错或重复失败时，先按[根规则的知识检索要求](../../../AGENTS.md#3-会话开始与中断恢复)完成适用的检索，再进入下述调查、试改或重跑流程。

以观察 → 假设 → 针对性检查/改动 → 可比验证 → 结论推进。先复现或界定触发条件，再用日志、源码和实验支持根因；一次未复现不足以证明修复。没有新增证据时先改变调查方法，不盲目重复试改/重跑。

日志分析先按[材料规范的采集流程](../../../docs/task-records.md#日志采集与分析)备份相关完整日志与 plog，记录来源、覆盖与缺口后分析；模型精度分析按该规范的远端保留例外执行。容器修改和环境记录使用同一规范的最小记录及总表。叠加多个 PR 时按其中的[顺序叠加流程](../../../docs/task-records.md#pr-顺序叠加)逐个保留原始提交与来源，不能用直接改源码冒充叠加。

中途接手手动测试时按[接手规则](../../../docs/task-records.md#接手手动测试)识别实际运行，正式测试无表项先补登记，再关联本次分析；调参排障仍留任务目录。SWE 数据集评测按原 runner 执行及其正式表登记，不借用性能测试字段或假定 AISBench 支持该 runner。算子工作按[进度与运行日志规范](../../../docs/task-records.md#算子开发进度与运行日志)同时记录决策进度和每轮完整日志，原执行工具及必要状态不另建替代品。

遇到超时或调整等待后仍在固定时长失败时，先定位最早返回超时的调用层，核对预算单位、读取时机和实际生效值；按需检查建链、重试或排队是否受更短的外层期限限制。找到能解释失败的计时层后停止扩查；延长等待只增加容错，不等于根因已修复。

性能工作先确定基线、指标、工作负载、测量条件、波动标准和预算，再复用领域工具测量。记录当前代码、设备/软件、模型、输入、并发和设置；条件混杂时不声称收益。模型性能需要端到端证据，单算子收益只能证明该算子。精度工作先确定 reference、输入与阈值，不能擅自放宽。算子生产与泛 shape 的适用规则以任务接口和框架为准，不套给其他任务。

关键实验写入 `results/实验记录.md`：编号、假设/预期、改动、代码/环境、工作负载、命令/配置、基线/候选、run/manifest 引用、结果、结论与下一步。失败、退化和无定论均保留，详细产物按本轮编号分组；事实、推断、静态检查、真实路径/端到端运行与性能测量分别标明。

初版先验证基本正确性，每轮优化验证受影响路径/关键场景/边界，最终执行完整必需矩阵与集成。`results/验证矩阵.md` 保存覆盖摘要和证据入口，详细用例放同编号结果目录或实际报告；依据风险和等价覆盖选用例，不按固定数量凑覆盖。精度失败、必需回归失败时暂停相应性能验收，静态通过不替代真实运行。

资源由底层协调，先核对实际占用再运行；同一 NPU 的性能测量不得无协调并行。停止/清理只处理本任务已确认拥有的组件并核对结果，不因聊天结束认定已释放。

仅在产物搬迁/安装来源核对或原生扩展兼容问题涉及本次目标时，按需读 [运行探针与产物核对](../../../docs/runtime-tools.md)，选择公共 `artifact_manifest.py` 或 `native_import_probe.py`。前者只读核对显式覆盖的字节/版本，后者在已授权环境运行可信用例；不因文件一致自动导入、启动模型或增加 NPU 检查。原生用例须检查子进程最终退出状态，主体完成标记或中间报告不代表正常退出。远程调用沿用原执行工具，不由脚本管理资源。

生成式AISBench评测交付需要报告官方指标与有效回答时，可按[证据报告说明](../../../docs/aisbench-evidence.md)消费明确选定的已有结果。普通交付用基本检查；用户要求输出审计或已有格式/字符异常时才启用深度扫描。工具不改原评分，不自动发请求或判定模型精度通过。

拟入仓的代码、文档或 skill 按[跨机器复用规则](../../../docs/validation.md#开发与发布的跨机器复用规则)处理全部直接参考和运行输入：必需内容随仓发布或声明可获取的固定依赖，实际机器路径通过参数/本机配置提供。任务资料可用于查证，公开产物只提炼自包含方法及合成回归，原件及索引留本机；不得靠删除链接或 local-only 标记掩盖缺失依赖。修改公共执行入口/依赖时验证候选隔离副本，纯说明修改按引用与代表请求检查，不自动增加远端实验。

## CI 与提交

涉及 CI 时读当前 workflow 和具体失败 job，把 PR、head SHA、workflow/job、run、实际错误、归因依据、修复、本地验证、审核与复验写入 `results/CI记录.md`。分类可为代码/测试、依赖/构建、workflow、冲突/历史、基础设施或 unknown；无依据不称偶发。

冲突修复核对 CI 实际消费提交历史的方式。每轮完成改动与验证后提供可审核 diff/结果，默认等用户授权再提交、推送或发布；当前轮/有限范围已授权则直接执行。首次推送批准不扩展为无限后续 CI 修复，范围/停止条件来自任务记录。

新提交把检查重新绑定新 head SHA，记录实际终态。旧 SHA 的成功不覆盖新 SHA；queued/running/skipped 不能写 success。重跑必须有理由，未知结果先查询，保留原失败。

## 判断变化与退出

关键路线变化反馈证据、当前假设、理由、风险/替代项和下一步，不展示内部逐步思维链。改变语义、支持范围、必需验收或授权时先准备具体证据与选项，等待用户决定；其余授权工作继续。

完成或中断时回传实际改动、验证、证据、限制、底层运行/资源和下一步，交由 [review](../ascend-task-review/SKILL.md) 整合。必需项未执行或无定论保持阶段状态，不自动降低标准或标 completed。
