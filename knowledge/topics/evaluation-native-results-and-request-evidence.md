# 先认定run身份，再计算结果

基础口径复用[AISBench证据报告](../../docs/aisbench-evidence.md)、[性能对照](pd-performance-comparison.md)与[精度skill](../../.agents/skills/ascend-model-accuracy/SKILL.md)，不维护第二个分数转换工具。以下补充历史容易混淆的具体用法。

## 1. 性能的正式请求、预热与stable窗口

固定服务实例、角色/并行、双仓及配置、dataset/seed/输入文件、repeat_rate、CLI、生成API配置和源码版本。正式样本、前缀预热和客户端内部warmup分别记录；某场景一条CLI可能内部产生多份输出，不能造出第二条CLI。

native stable与全程CSV可能有不同分母，例如历史stable2304而全程2560；两套指标分别登记，未取得选择算法就不解释为什么排除那些请求。输出长度1时的TPOT `99999`等哨兵不当实测时延。配置repeat_rate=0.9不等于实际本地命中率90%，外部传输比率也不等于池回读。

循环重放逐组、逐场景记录结果，核对命令与源码身份并显式保留seed差异。目录数量不是结束数量，须对应真实exit及正式结果。客户端准备失败、参数缺失或门禁拒绝且没有发请求时，保留独立attempt，但不计作模型服务失败。共享WORK_PATH需要隔离的可写客户端/输出，不能为重放改共享源码。

## 2. 长生成拖尾不是“测试卡死”

输出上限、reasoning配置和请求总超时会影响尾部。历史80k输出且无总请求超时时，剩余少量D请求仍持续生成；无排队并不等于算子高效。结合活动请求、token差分和日志新鲜度，不从完成百分比线性外推结束时间。

DSpark平均接受长度、接受率、图模式、CPU长度同步与小batch通信是不同观测。静态发现某分支未捕获图可作为性能嫌疑，不能无trace/A-B就量化各自贡献或归因某PR。`use_layerwise`覆盖实际图模式的历史例子见[池化教程](a5-memcache-tiered-pooling-tutorial.md)。

## 3. 传输成功、答案完整与官方精度

HTTP/请求成功不表示答对。分别报告执行错误、空答案、异常字符/重复、答案提取、官方评分和退出状态。历史推理末尾长空格但仍有完整A–D答案，不能记作空回答；部分已落盘样本与gold不一致也不是全量正式精度。

MMMU应记录真实分母、scored/unscored、官方accuracy/stderr、sample_errors、输出空值、finish原因和exit。解析器字段因版本变化为null时，读取该版本的原生final header，而不是补造0分或沿用临时值。若原评分器存在随机回退，审计应识别是否真的触发，并核对记录分数与原提取逻辑；不改写官方结果再报更高精度。

多轮分别报告。例如一组1730题1403正确，另一实验的三轮1400/1402/1396正确应保留独立run及退出状态；它们不是同一轮快照，也不能仅凭分数差证明池化因果。新运行started、exit缺失、只有部分scored时，不提前称正式终态。

耗时明确起止：客户端start→真实exit、日志开始→评分写入和模型请求墙钟是不同指标。轮间调度等待不算服务实际测试时长，原机时钟与本机时区分别保留。

## 4. SWE部分结果与超时关系

未完成的SWE只报已结束/总题数、通过、未通过、异常/超时、活动与等待，并保留run/job身份。异常通常是未通过子集，不重复相加。历史14/113结束=6通过+2验证未通过+6超时，不是最终113题分数；另一个run的22/113、9通过13未通过不能混到旧run。

Agent出现乱码命令、语法错误或长时间不更新，后来通过验证也不抹去输出缺陷；保留错误窗口和最终状态，根因不明就写待定位。用户停止测试或撤回监控后，停止相应跟进不等于已核验所有远端资源释放。

## 5. usage分布、请求关联与采样偏差

prompt_tokens可能包含重复历史和缓存内容，不等于新增prefill工作量；cached_tokens=0不单独证明没有池命中。只统计有返回的调用会遗漏仍在途或失败请求。例如保存的1568条usage与runner1590存在22条差额，就不能外推完整调用集，也不能把已返回调用的长输入比例推广到全部。

response UUID可关联Agent、P日志和时间戳，但tool→assistant间隔含编排成本。P的prefill墙钟还可能包括调度/同步查询，不能当NPU算子时间。反复采到query栈、地址变化和单个worker等待都需保留，不能拼成一次SDK耗时或宣布瓶颈消失。

## 6. 文件证据与复查

大日志/原生eval可留原地，只收集正式CSV/JSON、必要配置、exit及最小来源。下载清单和hash字符串不证明文件当前仍可取得；核对实际路径/大小/哈希，并报告原件缺失。历史一批主日志清单对应原件未找到，另一批Meta日志能核对，两者不可混称完整备份。

被撤回的无原件数值不因后来新采样而恢复为真；新证据独立记录时间、实例与条件。更换评测器/评分器、请求模板、数据或服务版本后重新核对口径；无新实验时不更新原实验时间。
