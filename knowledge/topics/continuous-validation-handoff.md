# 让运行状态可被下一位检查者接手

既有任务规范见[任务材料](../../docs/task-records.md)、[每日归档](../../docs/daily-sync.md)；本条只补长期验证的使用例，不建立第二套任务状态服务。

1. 固定业务范围、实例身份、工作负载模板及停止条件。先识别用户已经排队的任务，不重复发起。模板包含真实CLI、生成配置、数据与源码版本，不能只记场景名称；种子变化单独声明。
2. 每次检查读取最新小checkpoint，确认owner、PID/starttime、容器及健康/模型身份，未知或查询超时保持unknown，不直接当服务中断，也不在未知时开下一项。
3. 一个检查只完成当前必要一步，保存run身份、进度、真实exit/错误、下一步、owner与证据入口后交还。远端任务持续运行不要求模型会话一直等待，下一位检查者不能借用旧会话身份操作其作业。
4. 已有测量未终态，不启动下一测量；阶段切换需核对真实原生结果，不靠目录数或外层exit。结果按每项/每组保留，不能只给综合平均。
5. 定时迁移需具体授权，先停旧任务并核验新归属及首次检查，再按阶段和预计结束时间调整同一个调度；状态不变且不可行动时安静。未经明确要求不新增定时器。
6. 确认原服务退出或身份替换时锁存停止后续循环，只清理归属明确的测试客户端/采样/转发，不擅自重启或关闭用户服务。

压缩提醒、检查频率和上传预算是具体客户端/用户选择，不在公共知识中固化个人阈值。工具失败能否开新会话还受客户端可用性限制，不能承诺必定自动恢复。

## 归档时与业务owner分离

固定证据截止，结合可读用户指令、授权/撤回、任务文件与真实结果；不能以title、mtime或completed代替意图和验收。另一owner在截止后写入进度时，保留其文件，用截止内不可变checkpoint归档；保留原指纹使下轮能识别增量，不将新终态提前纳入旧窗口。

用户授权某项实现、知识收录和Git发布是不同维度；已明确的授权不重复询问，未覆盖的业务操作不从归档范围推导。个人任务表、调度配置与运行回执留在本机，公共知识只收录可复用方法。流程例子不证明当前服务连续、资源已释放或原始材料仍可取得。
