# A5目标架构与独立能力标志

## 结论与触发条件

当编译metadata显示目标架构正确，某个runtime接口仍在kernel提交前返回不支持时，要继续核对影响代码生成的独立能力标志。框架查到正确芯片、`target.arch`正确，不能替代另一条检测链的结果。

2026-10-16历史现场中，容器缺少可执行的`npu-smi`，而该后端的PCI兜底判据也未匹配，导致`compile_on_910_95=false`。后端据此启用FFTS相关host启动分支，生成对`rtGetC2cCtrlAddr`的前置调用；该调用返回207000后提前结束，随后才出现worker abort等连带错误。

这是特定安装实现的历史故障链。公开原始材料和完整构建来源缺失，保持`candidate`，不外推为所有A5、Triton或CANN 9.2.0的通用缺陷。

## 原证据与结论层级

| 历史证据 | 支持的判断 | 边界 |
|---|---|---|
| 容器可执行文件和PCI检测输入 | 该次八节点的两项检测输入均不成立 | 不代表宿主不能正确识别设备 |
| 检测代码 | 芯片能力标志由PCI匹配与`npu-smi`结果取OR；命令异常会返回false | 仅对保存的安装实现成立 |
| 实际采样编译metadata | target为950DT，而独立能力标志为false | 只覆盖已取得该产物的节点，不能把未生成缓存算作通过 |
| host生成分支及一个节点的两份launcher反汇编 | 存在C2c前置调用，并在非零返回后退出 | 反汇编覆盖不扩展为全节点二进制核验 |
| 原生PLOG及安装头文件定义 | 采样准备任务返回207000；当时定义为FEATURE_NOT_SUPPORT，与207001内存申请错误不同 | 不能单凭错误码断言具体检测原因 |

本轮复核以上已保存材料，没有重新执行采样或修复验证。该链条解释了当次直接失败机制，历史恢复情况和其他后续问题应分别验收。

## 复核与处置方法

1. 从原生首错判断失败发生在host准备、kernel launch还是device执行；任务名出现在错误中不等于device kernel已开始运行。
2. 对照当前安装后端的实际检测代码、容器内输入、编译metadata及生成launcher，寻找会改变目标分支的独立标志。已有[容器环境检查](../../.agents/skills/ascend-agent-workflow/references/service-deployment.md)用于准备基线，本条补充故障因果判断，不另设日常检查阶段。
3. 进入已授权修复时，补齐相应检测输入，并在新进程及隔离缓存中确认重新生成的标志与launcher；保留旧缓存和失败证据。只改一个开关或只确认命令可执行，不足以证明缓存已重编译、采样或完整请求已通过。

单独禁用FFTS可能避开前置取址，但同一个能力标志还可能控制编译pipeline，不能据此直接认定完整修复。配置变化与服务重启沿当前任务授权处理。

## 不能推出的结论与复查触发

不能从worker SIGABRT、EngineCore退出、清理时属性错误或图模式名字直接推导首因；也不能将207000写成显存OOM。本文没有验证当前main、其他芯片、其他Triton发行包或所有kernel。

检测实现、后端版本、PCI可见性、命令输出格式、容器挂载或编译缓存变化后，重新核对上述链条。若只有相同错误码而没有匹配的检测输入和生成分支，保留为新问题，不直接套用历史根因。
