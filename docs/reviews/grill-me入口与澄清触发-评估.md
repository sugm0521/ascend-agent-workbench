- status: implemented
- 评估日期：2026-10-14；实施日期：2026-10-15，Asia/Shanghai
- 用户要求：先验证是否值得修改；评估完成后明确授权实施、提交并推送 main。已将两处候选落实到正式 workflow，外部依赖和全局配置未修改。
- 结论：值得对现有 `ascend-agent-workflow` 做两处窄修改，明确特化方法别名和持续任务的条件触发；不是新增澄清能力，也不另建 grill-me skill。

## 直接证据与已有覆盖

本轮实际遗漏：首次查找用户指定 grill-me 时只按技能目录名检索，未先使用已有能力映射；任务从小模型通路转为正式权重发布后的快速部署时，没有及时回到未决取舍。

已有规则已经覆盖核心原则：workflow 第2项要求仅询问影响目标/方案/授权/验收的取舍；第21行要求先查能力映射；AGENTS 要求主动查证与必要澄清，明确小任务不强制采访；框架第343、347、581行覆盖未知决策、重要目标变化和事实/取舍分工；planning 第12行要求充分明确目标并仅补问影响方案的取舍。

因此，不能把本次遗漏归为缺少整个 skill 或无澄清规则。主要是执行错误；可改进之处是用户别名在可见 description 中没有出现，以及 workflow 第2项用“新任务”开头、持续任务的目标/范围/验收变化触发散落在框架中。

## 最小候选

只涉及 `.agents/skills/ascend-agent-workflow/SKILL.md` 的 description 和现有第2项。

1. description 明确“采用项目特化的 grill-me”，帮助在技能目录的摘要层识别用户用语。
2. 第2项保留原事实查证与停止原则，明确新任务或目标/范围/验收实质变化时重新检查未决取舍；复用已有信息和授权，仅对影响决策的未知分轮集中问询、给出推荐；用户显式要求 grill-me/grilling 时从本入口执行；已有答复不重问。

不引入机器/模型/版本专属规则，不强制每次加载完整上游 grilling，不扩散到 planning/execution/review，不增加额外确认门槛。候选是对已有规则的就近明确，不是另建流程。

已采纳实现见 [workflow](../../.agents/skills/ascend-agent-workflow/SKILL.md)；原候选 diff 和检查输出保存在本机忽略缓存，不随发布上传。

## 代表场景规则走查

这是对候选指令与现有项目规则的静态走查；实施内容与候选一致，复用该场景结论，不是新 agent 的实际调用测试。

| 场景 | 候选与现有规则共同导出的行为 | 评估 |
| --- | --- | --- |
| 简单查询模型型号/单个版本 | 自行查证后直接回答，不形成额外采访 | 保持原路径 |
| 明确的小修改，范围和授权已齐备 | 检查现有信息后直接执行 | 保持原路径 |
| 首次形成方案，端到端验收含义不清 | 查可得事实，询问会改变方案的验收取舍并给推荐 | 原原则保留，入口更明确 |
| 同一任务从冒烟改为正式部署准备 | 复用旧答复，只查新增要求和未决事项 | 变化触发就近明确 |
| 用户改变目标，但新要求已完整说明 | 更新方案，无新增未决取舍则继续 | 不因“变化”强制询问 |
| 用户点名 grill-me，目录列表没有同名自有 skill | 从 workflow 的项目特化入口处理，查来源映射 | 别名与入口更明确 |
| hidden、版本、路径等事实可从文件/环境获取 | agent 自行查询，不让用户填写 | 保持原事实/决策边界 |
| 用户已明确部署容器与资源预算 | 复用答复，不重复确认 | 保持已有授权 |
| 已发一轮问题，用户只回答其中部分 | 保留已答项，待未答项；不重复已答问题 | 不制造循环问询 |
| 用户要求评估/只读调查 | 继续调查与评估，不将候选或建议当作实施授权 | 保持授权边界 |

走查未发现必须扩大触发范围或删减停止条件的理由。新增措辞只改变条件的可见性，不把所有请求都转成采访。
