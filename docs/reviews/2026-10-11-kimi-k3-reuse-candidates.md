## 1. 原生扩展探针

**为什么值得提取：** 既有记录中，子进程已输出导入完成标记，仍以 SIGABRT 结束。因此 JSON 报告存在、stdout 出现成功标记、模块导入返回都不足以判定通过。

**稳定接口：** 输入显式指定的探针用例、导入列表、环境变量覆盖、超时和输出目录。每个用例运行在独立子进程；输出退出码、信号、超时状态、日志路径、实际加载库路径和最终结果。环境变量采集采用允许列表，不保存凭据。

**必要改造：** 单用例超时不能中断其余用例；保留已经完成的记录；限制日志大小；将子进程内部的中间报告和父进程确认的最终报告分开。POSIX 的负信号返回值与 shell 的 128+signal 返回值需明确区分。复用原工具的远程执行和任务身份，不新建作业管理器。

**验证要求：** 正常退出、输出成功后 abort、超时、缺失模块四种用例；确认分类正确、失败证据保留、日志有大小边界。不得将某一次 libstdc++ 替换或 LD_PRELOAD 实验编码成自动修复策略；现有实验未证明通用根因。

## 2. 产物清单与一致性核对

**为什么值得提取：** 本任务已有四台机器的源码、FLA 安装文件和编译缓存核对，既有缓存记录包含 630 个编译文件的 SHA 一致性。适合复用到环境搬迁和后续精度测试的版本核查。

**稳定接口：** 输入明确的根目录、wheel、文件允许列表和清单；提供生成清单、只读比较、打包、受控恢复等分开的动作。输出逐项版本、路径、安装来源、文件大小、摘要和差异。缺失或不可读项显式标为未知或失败。

**必要改造：** 去除固定机器、用户名路径和包版本；大文件使用流式哈希；原生库按原始字节比较，仅对明确指定的文本启用换行规范化；正确处理 wheel 的 `.data/purelib` 映射。原始缓存不修改，瞬态文件过滤规则明确配置，打包结果另存。

**恢复边界：** 任务中的直接 `extractall('/')` 不能用于通用工具。必须校验目标目录、成员路径、路径穿越及链接，限制允许恢复的前缀，并恢复到明确的隔离目录。不得包含 SSH 文件、历史记录和无关容器内容。大型产物在服务器侧处理；原任务具有特定传输限制，后续发送清单或报告遵循[当前环境适用的传输约定](../guides/task-records.md#日志诊断)，不将历史限额推广为通用默认值。

**验证要求：** wheel 安装映射、原生库单字节变化、缺失文件、缓存过滤不改原文件、非法归档路径拒绝。文件一致不等于 ABI 兼容，需结合原生扩展探针。

## 3. 机器与容器只读清单

**为什么值得提取：** 本任务不能仅凭容器名称或创建时间识别归属。已有脚本使用 NPU PID → `/proc/PID/cgroup` → Docker 容器 ID 的关联方法，更适合作为复用基础。

**稳定接口：** 输入机器清单、可选容器筛选和网卡；输出带采集时间的 NPU 进程、实际容器 ID、镜像摘要、挂载、网络信息及探测错误。不内置特定 IP 或容器名称，不根据主机编号判断忙闲。

**必要改造：** 兼容 npu-smi 输出差异；解析失败不能当作空闲；处理 PID 消失、未知归属、Docker 不可用和主机时钟差异。远程连接复用原工具，不保存独立登录凭据或资源租约状态。

**验证要求：** 用保存的文本和 cgroup 样例验证正常占用、真实空闲、解析失败、未知归属和 PID 消失。该工具只读；wall、启动、停止、资源预留仍由任务明确授权和原工具管理。

## 4. AISBench 证据报告与样例采集

状态：implemented（2026-10-14）。[公共工具](../../scripts/aisbench_evidence_report.py)实现显式输入schema/解析器、官方指标保留、逐组/总汇、请求关联和有界输出审计样例；[调用说明](../tools/aisbench-evidence.md)集中维护边界。下层确定性adapter和精度阈值规则保持，工具不增加在线请求采集器或自己的回归判定。验证限定本机离线样例和已保存答案索引回放，不声称本轮远端/NPU验收。

**为什么值得提取：** 本次 GPQA 记录为 179/198，官方 extract_rate 为 100%，另有 4 个输出没有有效 A–D 答案。HTTP 成功、官方提取率、有效回答率和正确率必须分别呈现。已有脚本还能核对实际请求参数并采集少量真实输出。

**稳定接口：** 输入明确的 run 目录、数据集/解析器类型、预期样本数、请求参数、可选对照结果/验收阈值、样例数量和字节预算。输出官方指标、独立格式检查、请求与响应关联、token/finish_reason 统计、异常索引和标注为节选的样例。

**必要改造：** 不硬编码 198 题、81920 tokens、日期、端点或异常题号；不默认选择最新目录；保留官方报告原件。不同数据集使用显式 schema/解析适配器，不对所有评测强套 A–D 规则。JSONL 按实际 LF 行边界读取，避免输出中的 Unicode 分隔符被 `splitlines()` 误切。采集字段使用允许列表，不收集鉴权信息；完整长输出留在服务器，导出报告遵守字节预算。

**与评估时 skill 的关系：** 当时核对的下层 correctness skill 已有 AISBench 报告规范化与对照接口，应复用。其 `aisbench_adapter.py` 虽然提供 `--temperature`，但 `prepare` 会拒绝非零值，属于确定性精度对照流程。本次 temperature=1、top_p=1、reasoning_effort=max 属于采样评测，需要单独配置入口，保留原确定性模式约束。没有对照或阈值时报告测量结果，不自动判定精度通过。后续版本以实际下层声明为准。

**验证要求：** 请求缺失/重复、参数不符、HTTP 成功但无有效答案、Unicode 分隔符、输出超过预算；核对官方分数与独立检查的区别，保证节选与原响应可追溯。

## 现有 skill 的窄改进

以下保留初次评估建议。后续已实施的execution/review/dependencies入口及全局算子skill连续状态检查，见[开发记录](../maintenance/开发记录.md)中“2026-10-11：通用运行检查与 skill 条件化补充”；全局修改未随工作台Git发布，不是本次评估整理的修改对象。下层来源的建议不表示已获实施授权。

1. **`ascend-task-execution` / `ascend-task-review`：** 补充原生扩展子进程正常退出的检查入口；交接分别标注产物一致、运行环境可用、实际模型请求、PD 请求与状态传输证据。保留服务的任务明确记录生命周期要求，不能自动按普通基准流程停服务。已有资源归属和定向清理规则继续复用，不重复扩写。
2. **`ascend-workbench-dependencies`：** 对原生依赖增加按需的实际加载库、ABI 和退出状态证据。不要固定某一 GLIBCXX 版本或通用预加载策略。
3. **全局 `ascendc-operator-validation`：** 评估时已覆盖 output、状态写回、别名、保护区和图重放，不需要重建通用算子 skill。初次建议增补：`None` 返回值与直接写回分别检查；连续两次 decode 使用同一份已修改的 state；分别报告逐步误差和累积误差。历史任务中的独立 FP32 golden、BF16 转换及带 stride 的保护状态夹具提供方法依据，具体 KDA 数学参考仍按算子维护。初次评估未修改该全局来源；后续已确认的连续状态规则按上述开发记录实施。
4. **下层 correctness / PD serving skill：** 保留现有接口与角色编排。采样评测适配和模型特定状态传输验证可提出补充建议；下层 `deps/` 来源本次只读，不直接改维护源。不要因环境交接完成就另建一个声称八机 PD 已验证的 skill。

算子证据来自2026-10-08的recurrent与chunk路径历史验证，原业务记录未随公共工具发布。前者已有两实现、七组用例、连续两步共 28 次调用；后者说明 final state 一致仍不能代替 output 正确性判定。此处只保留历史摘要及其限制，不提供本机原始材料索引。

## 暂不推广

- 任务专用容器创建脚本：当时有任务专用的名称、特权挂载和重建逻辑。公共化前必须有明确创建/复用计划、真实归属校验和隔离路径，不能照搬自动删除已有容器的行为。
- 任务专用C++运行时准备脚本：代理、证书、具体 GCC 版本和动态库替换依赖当时环境，保留为任务实验。
- 整套 Kimi K3 四机/八机硬编码启动与交接脚本：机器、镜像、网卡、版本和占用结论会漂移；报告生成应消费实时清单，而不能固化历史状态。

## 历史落地建议与后续边界

初次评估建议先确认具体候选，再依次提取原生探针、产物核对、只读清单与AISBench报告。后续实际决定以上方候选表为准：探针、只读产物核对和报告已有正式入口，机器清单继续deferred，打包/恢复未实施。不重复提出已落地工具；未实施项只有在新增证据或明确建设请求下重新评估，不因保留历史接口设计自动继续建设或运行远端验证。
