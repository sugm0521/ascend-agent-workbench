# 干净克隆验证

所需运行时为 Python 3.10+、Git 和 Node.js 22.12+。周报渲染的 `marked` 版本由仓库的 `package.json` / `package-lock.json` 固定；不需要当前作者的客户端缓存、私有模块目录或历史实验文件。

在新克隆的工作台根运行：

```sh
npm ci --ignore-scripts
python scripts/validate_workbench.py
```

依赖安装采用所选网络环境的正常 registry/proxy/CA 配置，不关闭 TLS 验证。安装目录 `node_modules/` 不提交。统一检查覆盖根测试、真实 Node 渲染和 HCCL helper 的合成测试；不连接服务器、不占用 NPU、不安装领域子模块或启动模型。平台权限或 POSIX 语义导致的用例跳过会在摘要中列出，不能当作该分支已实测。

## 可选客户端集成

默认从 `NODE_BINARY` 或 PATH 定位 Node，使用项目安装的 `marked`。已有兼容运行时可用 `--node` 指定；`--node-modules` / `NODE_PATH` 仅用于现有环境的附加模块搜索，不是干净克隆的必需条件。

客户端提供的 skill-creator `quick_validate.py` 是可选的附加格式检查；可通过 `--skill-validator` 指向实际可用校验器，缺省会明确报告未执行。它不参与项目代码、报告渲染或根测试的必需执行路径。涉及 skill 修改时仍按相应 skill 开发规范完成适用校验，不伪造未运行的结果。

根目录 `tests/` 已包含 HCCL helper 的合成套件，统一入口和直接执行 `python -m unittest discover -s tests -v` 都会发现它。直接运行根测试时缺 Node/marked 可能跳过渲染；统一入口会提前报告依赖缺口，不以漏测代替完整通过。

历史任务中的个人进度、原始回执和运行资料留本机；公共文档引用维护中的说明、源码和测试。可复用的流程走查输入见[框架演练场景](项目框架.md#15-第一轮流程演练)，GPQA 客户端辅助代码见[调用说明](gpqa-batch.md)。干净副本的本地回归不需要 `tasks/`、作者初始化报告或历史运行目录。

## 开发与发布的跨机器复用规则

适用于拟进入仓库的代码、文档、skill 正文及其 references/scripts/assets，以及从 agent 结果提炼的公开内容。本机调查、初始化配置和运行记录仍可使用实际路径与私有证据；这些材料与索引留在忽略目录，不作为公开产物的必需输入。

1. **规划与委派**：有可发布改动时，在任务及 assignment 中写明拟发布文件、仅供调查的本机输入和适用验收。主、子 agent 都按此边界产出；本机结果单独回传，不能直接把任务报告或来源清单复制入公开文档。
2. **选用与转化参考**：必需说明和回归材料随仓库维护，仓内引用使用相对路径；外部来源使用读者可获取的固定版本并注明适用条件，借用实质内容保留来源和许可。可以从本机资料提炼自包含方法、最小合成示例与结论边界，但不得带入实际私有路径、原材料文件名、大小、哈希或其他索引，也不得仅删掉链接后保留对该材料的隐含依赖。缺少必需材料时补齐可发布替代或保留未完成状态；历史结果摘要须说明无法独立复验的限制，不伪造公开证据。
3. **实现可配置入口**：运行所需路径、身份和资源由使用者的参数、本机配置或现有能力发现提供；示例用通用占位值并说明如何获得实际值。必需运行时、包、工具和数据需有明确版本约束、获取及准备方法；按现有声明固定可锁定依赖。不能依靠作者缓存、全局个人 skill、会话记忆或未声明的模块搜索路径才能执行。可选能力说明启用条件和缺失处理，不把实际必需项降为可选。
4. **检查真实候选**：交付前检查本轮候选内容与全部直接引用，包括脚本、配置和普通文本中的依赖，不只检查 Markdown 链接。发布白名单、已跟踪的旧材料和历史快照同样受约束；新增忽略规则不等于移除已跟踪文件。无论原始材料是否存在于当前机器，都不能据此放行公开引用或索引。
5. **按改动验证**：仅改文档/skill 流程时，检查候选引用、格式及适用/不适用请求的决策，无需重跑无关代码或远端实验。新增或修改公共脚本、必需依赖、安装/执行入口时，在最终候选 Git 树的隔离副本中，只按已发布说明准备声明依赖，排除作者额外注入的缓存和模块搜索路径，再运行受影响的代表路径与缺依赖分支；最小回归输入随仓库提供。文档声明的环境配置仍按其要求准备，缺设备不编造运行。

报告区分候选引用通过、隔离副本运行通过和真实其他主机/平台验收；前两项不自动证明第三项。必需复用路径未验证时保留明确缺口，不用当前机器“能跑”宣称完成。检查与修改不扩大提交、推送、安装外部能力或远程运行授权。

## 发布引用检查

引用检查使用 Git 候选文件集，不依赖当前机器的文件存在性。已忽略文件、已删除文件或作者本机材料不能满足仓内引用。检查最终提交树：

```sh
python scripts/validate_workbench.py --links-only --links-ref HEAD
```

`--links-ref` 只选择文档来源；工具和测试仍来自当前工作目录。默认候选集包括未被忽略的新文件，发布时还须核对最终提交白名单。

本机原始资料及其路径、文件名、大小和哈希索引不进入仓库。缺失文件链接、作者本机绝对文件链接一律报错；`local-only` 标签和历史任务目录没有放行例外。原始实验可在个人环境保留，仓库正文须给出自包含的方法与结论边界，必要代码、合成回归材料必须随仓库发布。

领域依赖允许按用途未初始化，因此本检查单独列出依赖仓链接未验项；其固定来源与准备方法由 README、source lock 及 init/dependencies 管理。检查不验证外部网站、文内锚点或所有 Markdown 语法，也不把合成回归当作真实 HCCL/NPU/模型验收。

## 私有知识边界检查

默认引用检查拒绝公开树中 `knowledge/README.md` 以外的知识文件；`--links-ref <ref>` 同样检查指定提交树，不因工作区已删除或加入 ignore 而放行已跟踪正文。公开仓验证无需本机配置或私有知识库。新增主题与历史只能写初始化绑定的外部私有目录。

如需验收已选目录，由 agent 读取忽略的 YAML 取出 `paths.knowledge_root`，在工作台根调用知识入口的 `--knowledge-root` / `--knowledge-path` / `--knowledge-only` 只读检查。脚本不解析 YAML、不创建目录、不写知识、不同步 Git；ready 只说明真实外部目录当前可读。根测试覆盖未配置、不同开发者目录、目录缺失、路径越界和公开提交树拦截；符号链接权限不足时如实跳过对应案例。
