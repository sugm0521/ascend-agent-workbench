# 分层协作与直接启动

主skill组织目标和跨领域任务，领域入口选择场景与方法，具体能力实现本轮步骤；共用planning/execution/review和运行快照按需复用。层级不等于新agent、问卷或任务。

| 从哪里开始 | 当前执行者的职责 |
|---|---|
| 主workflow | 复用目标/授权/任务信息，选领域；跨域目标安排阶段、交接和总交付 |
| 领域入口 | 目标域已知，直接选细分能力并核对前提；跨域或总目标改变时交主workflow |
| 具体能力 | 复用当前任务，先核对所属领域的适用/选用规则；覆盖不足交领域重选，不强制完整回跑主入口 |

一个任务只有一份当前状态和owner。交接带目标、已定取舍、输入/版本、授权、有效知识查询、工具绑定、证据及缺口；已有信息直接使用。直接点名能力是用户给出的偏好，不是绕过授权或适用范围。

## 知识在业务运行中的触发

沿用[知识接入与检索](../../knowledge/README.md#目录绑定与检索)。从本机配置解析私有根，按其规则/导航和对象、症状、版本、参数定向查有效主题，再读命中相关内容；不只看标题。

- 首次进入工程目标，尚无覆盖本目标/条件的有效结果：由当前入口查询。主入口可交领域完成，执行前取得结果。
- 新错误、重复失败准备重试，或调查转向/关键条件变化：实际处理者定向补查或复核适用性。已有查询仍有效则复用，不重复全库扫描。
- 新操作/验收判断未被已有知识覆盖时补查。简单事实问答、纯转录/汇总或已有充分结果无需额外检索。
- 查询摘要留当前任务：范围、命中及采用判断、版本/证据限制，必要时记hit/no_hit/unavailable/reused；不建第二套状态或全局缓存。

candidate用于假设/用例，verified也受原版本和证据层级限制；均不能替代本轮实际代码/运行。未配置、不可读与未命中分开，独立源码调查可继续，不自动初始化或写库。私有正文及其原始材料索引不进入公开skill；新经验按原收录授权提出候选。

## 可选的项目改进反馈

主、领域或具体能力入口发现具体skill缺口、改进价值或新增有效验证证据时，先按[参与偏好](../../.agents/skills/ascend-workbench-init/references/config-schema.md#项目改进参与偏好)核对本机选择。仅明确参加时，由当前任务负责人在合适的收尾点邀请一次；未选择、不参加或无新价值时不主动询问，不因此重跑初始化。同一事件在各层交接中去重，已在反馈流程中不重复邀请。该偏好不影响正常错误报告、验收和业务交付。

使用者主动要求反馈时，可直接交[工作台维护域的反馈流程](../../.agents/skills/ascend-workbench-maintenance/references/skill-feedback.md)，无需先改变长期偏好。参加仅允许按需邀请，不自动收集或投稿；整理与发布分别判断，公开发布必须通过[当次最终资料审核](../../AGENTS.md#4-授权与关键判断反馈)。

## 自有优先与上游发现

先核对输入输出、版本/芯片、实际工具和验证范围；适用且已验证的自有能力优先。自有覆盖不足、缺陷或必需前提不适用时，核对上游方法/工具后补位。复用原脚本/模板，选择性融合方法与项目改进，不复制整仓或平行启用多套完整流程。

领域选择未命中/不足，或新错误、失败和转向暴露缺口时，领域负责按[依赖能力发现](../../upstream/skill-mapping.md#依赖能力发现入口)检索已登记来源；先相关源，必要时扩大其他已登记源摘要，足够即停。具体能力把缺口交所属领域。目录不是白名单，单任务选用不自动改变公共默认策略、升级/安装或建新skill。

实际采用关系以各模块references/upstream-usage.json及其说明为准；[消费与升级约定](../maintenance/upstream-consumption.md)区分调用、规则引用、方法/模板引用和历史溯源。检索到候选不等于工具可用，缺前提只阻塞相应步骤。

## 来源与执行边界

来源锁与本机配置定位唯一上游固定副本；deps不承载任务修改，产物/必要差异用任务、业务目录或可写执行副本。方法引用无需每次重读全仓；实际工具版本/接口与当前provider须分别核实。沿用原身份、设备、端口和执行状态，不建第二套运行系统。上游宽泛触发、默认机器/cron、提交或完整修复循环不扩大授权。

迁移后所有当前调用方使用正式路径，移除迁出位置的兼容跳转/别名；项目指向当前维护源的接入联接可建立/替换，不承诺旧名。角色metadata是维护信息，不是客户端强制调度器；入口发现和真实行为须分别验证。
