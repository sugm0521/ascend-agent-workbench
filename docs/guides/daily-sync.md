# 本机归档、知识维护与授权发布

本文只定义可复用的方法与发布边界。具体调度时间、个人持续授权、应用任务提示和运行回执由本机维护，不写入项目仓库；没有具体授权时不得据本文自动发布。

## 先检索当前项目，再归档

1. 核对实际Git根、当前HEAD、相关暂存/未暂存差异和新增维护文件，固定本轮读取截止。成功回执只是增量线索，当前项目内容才是知识与skill现状；同时纳入手工、其他会话与自动维护的变化。
2. 从本机上次成功截止检查变化。缺回执时做有界首轮检查，说明实际覆盖；后续覆盖遗漏区间，不把所有旧文件算作新工作。先读任务/交付小摘要，必要时再读对应日志片段或产物。
3. 个人日报保存到忽略目录 `.workbench-local/daily-sync/daily/YYYY-MM-DD.md`，记录实际工作、结果、验证层级、未完成与来源。同日重跑更新相应覆盖，不复制原始会话/大日志。任务说明仍是状态入口，不为归档改owner、重跑实验或操作服务。
4. `tasks/`、`records/`、个人日报/周报、候选patch、定时配置和运行回执均为本机资料，不纳入提交。records 中的口令不进入归档摘要、会话回传或候选审视材料。旧 `knowledge/daily/` 只作已有记录兼容，不再新增或发布处理进度。忽略规则不会自动移除已有Git跟踪，发布时仍须排除这些路径的差异，不自动重写历史。

日报、周报和候选评估的原始材料不属于公开知识；有证据、可复用的工程判断才进入主题。不能把个人进度放进知识条目来绕过边界。

本机原始资料的路径、文件名、字节数和哈希索引同样留本机，不发布指向它们的链接或清单。入仓内容必须具备完整的方法、结论边界和必需材料；所需外部依赖声明可获取的固定来源，不能靠 local-only 或历史记录例外掩盖缺失文件。

## 知识归纳

将本次归档范围内的任务摘要和必要证据交给[知识skill](../../.agents/skills/ascend-knowledge-curation/SKILL.md)，先读取绑定库的 AGENTS.md、首页及相关分类规则；只处理当次指定材料及必要关联证据，不自动扩展为旧任务补录。候选范围、检索去重、证据时间、状态复核和历史保存统一遵循[知识库协议](../../knowledge/README.md#统一证据流程)，本文不另维护处理细节。

知识正文、索引和历史只写入本机配置 `paths.knowledge_root` 指向的外部私有目录；未配置或不可读时记录缺口，待确认候选留本机，不回退公开目录或启动完整初始化。具体收录由用户逐条决定，已有指定内容的授权直接沿用；日常归档、持续发布或同步授权不自动批准未确认候选。普通过程保留在本机日报，归档回执不能替代知识核实结果。

## 检查遗漏并推送

初始化的[远端与维护选择](../../.agents/skills/ascend-workbench-init/references/config-schema.md#私有知识库的远端与维护选择)分别控制知识接入：不使用远端时仅维护本地；手动同步时定时整理只列待同步项，具体用户授权的当次提交推送按其范围处理。automatic 还须有对应私有目标/子树/操作的明确授权；缺字段不自动开启推送，也不改变已确认的既有调度或阻断本地知识能力。定时维护授权与知识候选收录、远端创建/同步授权分别核对。

即使检查发现其他未提交内容，持续维护也仅在当前明确授权内处理：

| 内容 | 处理边界 |
|---|---|
| 项目自有skill新增/优化及其必需入口、规范或随附工具 | 有具体实施授权，已完成适用验证，内容稳定且无其他owner继续写入后，才可纳入对应发布 |
| 私有知识主题、索引及必要历史快照/原因 | 具体收录/修改已获用户确认，证据、去重、适用边界与历史检查通过，并有对应私有 Git 提交/同步授权后，才可在已核对的私有目标中处理；禁止混入公开工作台发布 |
| 任务进度、日报/周报、定时配置、回执、原始证据、未确认提案及其他代码/依赖改动 | 留本机并说明；不因每日检查或task completed而自动取得发布授权 |

不能凭维护授权实施新skill候选、业务功能或依赖升级。skill优化提案由[candidate-review](../../.agents/skills/ascend-skill-candidate-review/SKILL.md)评估，实施需另有具体确认。手工修改不自动等于完成、核实或可发布。业务仓和外部依赖源码不混入工作台发布，PR描述按原授权处理。

两个目标仓分别核对身份、私有性（知识仓）、Git 根、分支与全部 outgoing。知识目录是笔记仓子目录时，只纳入该子树，不运行会 add 全库的同步脚本。公开 knowledge/ 只允许 `README.md` 通用协议与 `templates/AGENTS.example.md` 初始规范模板，不保留正文、历史或指向私有目录的机器链接。发布时列逐文件/hunk白名单，关联授权、验证及当前内容指纹，并审查所有outgoing提交，防止夹带旧的任务进度或未授权内容。隔离准备并保留其他dirty/staged；不add全部、reset/clean、强推或stash全工作区。代码身份/DCO、目标、适用检查与远端SHA按根规则核实；Git上传大小仅在本机配置 `git.push.max_upload_bytes` 启用限额时按[配置约定](../maintenance/validation.md#git-推送大小配置)核实；发布前发现内容或owner变化就重新审查。

归档、私有知识同步与公开 skill 发布分别保存本机回执，不共用成功状态。归档完整后才推进归档覆盖截止；知识证据不全时把具体缺口和未完成项列入后续队列，不能将缺口写成成功。私有同步或公开发布只有独立回读对应远端 SHA 成功后才推进各自发布位置；失败保留该仓上次成功位置，不回退已经完成的归档。回执存入 `.workbench-local/daily-sync/`，记录覆盖、逐文件/hunk白名单、验证、实际提交与远端回读、保留项；上传包大小仅在配置启用限额时记录，否则注明未启用大小限制。同一输入重跑语义去重，不重复提交；没有变化不制造空提交。

## 推送后的详细反馈

在本次独立运行结果中说明：实际覆盖；每项发布的skill/知识改动前后、原因、依据与限制；完整文件清单；实际验证与未执行项；提交链接、远端回读、DCO及大小限制状态（启用时附包大小检查结果）；没有发布的内容及原因。个人任务进展可以在本机结果中汇报，不随反馈上传GitHub。

## 周报入口

明确周报请求使用[ascend-weekly-report](../../.agents/skills/ascend-weekly-report/SKILL.md)，生成个人工作、项目与知识改进两份本机报告，并提供阅读/打印版。报告方法与样式由该skill维护，调度器只传入本机项目、窗口与输出位置；不在此维护第二份周报模板或个人时间。
