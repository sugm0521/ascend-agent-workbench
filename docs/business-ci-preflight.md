# 业务仓推送前 CI 预检

适用于工作台执行 vLLM、vLLM-Ascend 代码修改后准备推送的阶段。由执行 skill 组织、验收 skill 核对，沿用任务说明和 `results/CI记录.md`，不新建调度器、Git hook 或另一套执行状态。普通分析、源码问答及无推送准备的初始化不触发业务测试。其他任务已明确要求的硬件验收仍独立处理；本预检不运行 NPU 用例、模型服务、分布式或性能测试，不替代远端 CI。

## 候选与检查选择

1. 核对实际 Git 根、目标分支、远端引用新鲜度、全部 outgoing 提交和本轮授权文件/hunk；已有未提交及其他会话内容保留。明确实际待推送内容，不能只看最后一笔提交或把整个dirty工作区当作候选。
2. 读取实际目标版本及候选中的项目规则、CI workflow、pre-commit 配置和被调用脚本；追踪相关路径过滤、工具固定版本、执行阶段和命令，含 GitHub Actions 之外的实际CI入口。候选修改CI配置时同时审查基线与候选，不能靠删门禁获得通过。不可访问的定义和托管侧必需检查保留未知，不臆造完整门禁清单。
3. 在已有CI记录中列出选定/不适用/仅远端执行的检查及理由。复用仓库原配置，不在工作台复制一套lint规则；静态检查按适用文件类型执行，CI要求全量或 `manual` 阶段时不能只跑默认阶段或悄悄缩为改动文件。

| 改动 | 本地预检选择 |
|---|---|
| 文档、注释、格式 | 对应格式、拼写、链接等静态检查；通常不运行CPU用例，含可执行内容或影响行为时另行判断 |
| 代码 | 适用的格式、lint、类型及项目自定义静态检查；类型检查是否需依赖按原入口核对 |
| 逻辑、接口、依赖、测试 | 按调用/依赖影响、原CI选择规则及现有测试选相关CPU用例；不默认每次提交或每次推送全跑 |
| 仅硬件路径可验证的改动 | 能执行的静态检查及相关CPU覆盖，明确剩余硬件缺口；不启动NPU测试，不将mock/CPU通过说成硬件正确 |

CPU用例先核对fixture、import、依赖和执行脚本，不依赖名称判断；可能占用NPU、启动服务或分布式进程的测试不执行。目标CI要求超出本轮CPU/静态范围的检查列为仅远端验证，不擅自删除要求。

## 环境发现与隔离

- 本机兼容则本机执行；需要Linux时依次查当前任务明确环境、本机初始化报告/服务器记录、已保存SSH配置及适用密钥引用。使用现有远程工具/provider及真实会话身份，不借用其他会话绑定，不另造SSH或资源状态。历史记录与密钥只提供候选，先只读核验连接、身份、平台、Python/工具版本、容器/目录归属及现有服务，不输出密钥或凭据。
- 匹配后在已有授权内自动复用，无需重复询问已有选择；缺适用目标、凭据、权限或依赖时报告具体缺口。能连接不代表适合运行；不修改共享环境、不影响服务，不因发现SSH配置自动安装系统依赖、新建容器或申请NPU。确需额外副作用时先说明具体方案并取得对应授权。
- 使用任务专用隔离副本及虚拟环境，核对最终候选内容在执行端一致；按声明准备任务内依赖，避免污染共享环境。源码和配置传输遵守独立传输限制，不能把Git限额关闭解释成允许无限发送远程载荷；无法在限制内准备候选就记录缺口，不自动上传大仓快照。
- 自动格式修复只作用于隔离副本，保留修复diff并核对是否属于本轮范围，再定向应用及复验，不覆盖其他工作。结束只清理确认归属本任务的临时进程和资源；需要保留的材料沿用现有任务规范。
- 初始化只发现并登记可用性，CPU检查环境无需NPU硬件准入；缺远程环境不妨碍本机静态检查。实际预检核对记录新鲜度，不运行完整初始化来绕过缺口。

## 证据与复用

在既有CI记录中保存候选SHA（未提交候选另记内容指纹及基线）、目标/配置版本、工具版本、环境标识、检查范围/选择理由、原命令、退出码、通过/失败/未完成、跳过原因和完整输出位置。远端记录实际容器/目录与候选一致性；skipped、超时或中间成功标记不是通过。

相同候选输入、检查配置、工具/依赖与环境的结果可复用；仅生成提交或重试推送不必全重跑，但必须确认检查不消费提交历史。改代码、配置、目标基线、相关依赖/环境或历史敏感输入后，按影响重跑失效项；不能把旧SHA绿灯直接覆盖新候选。跨机器复用保留环境差异及未验证项。

## 失败、修复与推送决定

| 情形 | 处理 |
|---|---|
| 可自动修复的格式问题 | 隔离修复，审查diff并重跑相关检查，修复纳入本轮审核 |
| 本轮代码导致失败 | 有本轮修复授权则在范围内修复和复验；仅预检/审查授权则交付证据和建议 |
| 环境或依赖故障 | 区分代码失败，核对兼容环境，不擅自改共享环境或系统依赖 |
| 疑似基线已有失败 | 必要时用相同环境、命令与适用输入对照基线，记录与本轮的关系，不顺手扩大修复 |
| 超时、断连、输出不完整 | 先查实际进程与退出状态，保留未完成；有原因才重试，未知终态不重复启动 |

保留首次失败、分类依据、修复diff与复验；无法归因则记unknown。不得跳过检查、放宽标准、删除用例或无限重试以取得通过。CPU失败不自动扩大为NPU验证；修复改变其他检查输入时补跑对应失效项。

未解决的本地失败或必需项未完成默认暂停推送；也不一刀切禁止带问题推送。推送时逐项给出实际问题、候选内容、与本轮关系、影响、替代证据及建议，取得用户对带这些问题推送的明确同意，并记录例外范围。普通提交/推送授权不覆盖未披露的失败；新增问题或候选变化后重新判断原同意是否仍适用。例外只允许该次推送，不将失败改记通过、不降低最终验收标准。

仅远端CI可执行或明确排除的NPU检查列为未验证，按已有具体推送授权处理，不为每个已知远端待跑项重复索取例外。用户另有必需验收要求时沿用其边界。推送前仍核对授权、范围、身份/DCO、敏感内容及[可选上传大小策略](validation.md#git-推送大小配置)，不修改PR描述。推送后核对远端SHA及其CI状态；远端失败修复沿用原授权范围，首次批准不扩展为无限后续修复。
